# L2 가설 생성 구현 계획

L2는 사용자 질의에 해당하는 후보물질의 후보(candidate)를 생성하고 근거를 계산하여, L3에 전달하는 역할을 담당한다. 기존 에이전트(Origene, RegNetAgents 등)의 아키텍처 구조는 크게 다르지 않다.

따라서, 해당 아키텍처의 구조를 설명하면서 구현 계획을 검토하는 문서이다.

---
## 용어
- **MR** : Mendelian Randomization, 멘델 유전학적 무작위화


## 후보물질 가설 목록 생성

[후보물질 가설 생성 목록 생성 아키텍처](../images/candidate_hypothesis_generation_architecture.svg.svg)


Origene의 후보물질 가설 생성 파이프라인과 수집 도구 및 쿼리 정제 로직은 다음과 같다:

```
[원시 검색 텍스트 (PubMed, Tavily, Assay 등)]
     │
     ▼ 1단계: 정규식 마이닝 (\b[A-Z0-9]{2,10}\b & 내장 불용어 제거)
[질의 전처리] : 정규식 마이닝 및 하드 규칙, LLM 정제 적용
     │
[유전자 후보 풀] ◄─── LLM 가설 확장: 접두사 힌트를 기반으로 신규 유전자를 제안합니다.
     │                                  
     ▼ 통계 기반 정렬 & Pinning: 최근 등장 일자와 출현 횟수를 기준으로 내림차순하여 비교적 최근, 그리고 많이 언급된 유전자를 우선시합니다.
[최종 후보 풀 (최대 250개)]
```

### 질의 전처리 디테일

1. **텍스트 마이닝**
    - 검색 결과 텍스트에서 정규식(`\b[A-Z0-9]{2,10}\b`)으로 대문자 토큰을 수집하고, `DNA`, `RNA`, `ATP`, `FDA`, `IC50` 등 내장 불용어(Stopwords) 및 순수 숫자를 제거합니다.
2. **하드 규칙 정제**
    - 코드 레벨에서 모호한 약어/패밀리명(`ER`, `CYP`, `AKT`, `JNK`, `JNK1`, `CRAF`, `53BP1`), 숫자가 안 붙은 불완전 접두사(`AKR1C`), 2자 이하 단어(`AR` 유전자 제외)를 강제 제거합니다.
3. **LLM 2차 필터링**
    - LLM을 이용해 바이오 문맥상 실체하는 인간 HGNC 유전자 Symbol(예: `FGFR4`, `SLC7A11`)만 선별합니다.

### 후보물질 가설 발산 및 확장

LLM을 활용하여 외부 DB에 검색되지 않더라도, 질환 맥락상 제안될 수 있는 미탐색 타겟을 수집합니다. 예를 들어, 후보 유전자가 `SLC7A11`일 경우, LLM은 해당 유전자의 패밀리인 `SLC`를 인식하고, 질환 맥락에 맞는 다른 `SLC` 유전자를 후보로 제안할 수 있습니다.

### 후보물질 수집 도구 및 입력 쿼리 정제 (Query Sanitization)

OriGene은 수집 도구의 특성에 따라 3가지 유형으로 분류하고, 자연어 질의로 인한 API 에러나 성능 저하를 막기 위해 2중 입력 정제 가드레일을 적용합니다.

ToolSelector 내부에서 바이오 엔티티 네트워크인 KGNetwork, 임베딩 검색기 ToolEmbeddingRetriever, 그리고 GeneralToolSelector와 ExpertToolSelector가 객체로 만들어지며 사용됩니다.

#### 수집 도구 분류
**문헌/웹 검색 도구**:
     - `paper_search` (학술 논문 DB)
     - `pubmed_search` (PubMed DB)
     - `tavily_search` (최신 웹/리포트)

**바이오 DB 검색 도구**:
     - `search_target` (ChEMBL/OpenTargets 타겟)
     - `search_assay` (실험 어세이)
     - `search_activity` (화합물 결합 활성)
     - `get_general_info_by_protein_or_gene_name` (단백질 프로필)

**임상 오믹스 분석 도구**:
     - `tcga_immune_correlation_analysis` (TCGA 암 환자 면역/발현체 데이터)

#### 도구별 입력 쿼리 정제 방식
**문헌 검색 쿼리 정제 (`GeneralToolSelector`)**:
     - LLM이 자연어 서브 쿼리에서 `"drug"`, `"target"`, `"disease"` 같은 추상어/불필요어 조사를 떼어내고 핵심 바이오 키워드 조합으로 변환합니다.

**DB 검색 쿼리 정제 (`ExpertToolSelector`)**:
     - 자연어 문장에서 23가지 바이오 고유명사 엔티티만 추출한 뒤, `entity_filter`를 통해 `"effective drug"`, `"Mutation"` 같은 무의미한 일반 단어를 제거하여 DB 검색이 가능한 단일 엔티티 파라미터로 정제합니다.

**오믹스/온톨로지 하드 가드레일 (`ToolSelector.run`)**:
     - `get_ontology_name`: 쿼리가 40자를 초과하거나 띄어쓰기(공백)가 포함되면 Ensembl 400 에러 방지를 위해 코드 레벨에서 즉시 차단/제거.
     - `get_gene_specific_expression_in_cancer_type`: 쿼리가 2~20자 길이의 깨끗한 HGNC 유전자 Symbol(예: `EGFR`, `CXCR4`)이 아닌 자연어 문장인 경우 코드 레벨에서 즉시 차단/제거.

### 질의 정제 (Query Sanitization)

|구 분류|정제 전 (Before)|정제 후 (After)|정제 목적|
|---|---|---|---|
|문헌 검색|"Harvest a candidate name list in Glioblastoma and find effective targets"|"query": "glioblastoma extracellular surface receptors targets"|문장 ➔ 핵심 서치 키워드 변환|
|바이오 DB|"appropriate target molecules for Rheumatoid Arthritis"|"query": "Rheumatoid Arthritis"|추상어 제거 ➔ 단일 고유명사 추출|
|오믹스 DB|"gene": "EGFR receptor signaling pathway"|"gene": "EGFR" (2~20자 정제 Symbol만 통과)|API 400 에러 및 유효하지 않은 쿼리 파기|

## 가설 우선순위 선별

이 단계의 핵심 목적은 아직 검증되지 않은 수십~수백 개의 타겟 중, 제한된 도구 호출 비용(API Cost & Rate Limit) 내에서 검증 효율이 가장 높은 12개(기본 배치 크기)의 유전자를 선별하는 것입니다.

### Origene 후보 선별

However, further development is needed to address OriGene's current limitations:
...
(i) its extensive tool set requires pre-defined rules and post-training techniques for improved efficiency and reduced topic drift;
...
(iii) its generated hypotheses necessitate refined scoring and filtering to address challenges in safety, testability, originality, and biological plausibility.

Origene은 표적 가설을 4가지 과제로 분리하였으며, 위 구절은 저자들이 남긴 3가지의 한계 중 하나이다. 즉, Origene의 표적 가설 생성 후 처리 과정을 형식화하여 균일하게 적용하고 근거를 추적가능한 형태로 바꾼다.

LLM 심사 이후 부터, 명시적인 도구 선언과 비교, 재현 가능한 가설 검증을 위해 

```
[후보 풀 (Pool)] 
    │
    ▼ 1. 최근성/빈도 정렬 후 상위 50개 추출 (shortlist)
[Shortlist (50개)] 
    │
    ▼ 2. LLM 심사 (_prescreen_symbols_for_validation_llm)
    ├── drop ──────────► 영구 삭제
    ├── deprioritized ──► 풀로 복귀 (다음 회차 재심사)
    └── selected (12개) 
            │
            ▼ 3. Pinning 등록 (_pinned_symbols)
            │
            ▼ 4. 생물학적 근거 타겟 검증 (_validate_candidate_symbols)
            ├─► MCP 1: GO Cellular Component (세포 위치)
            ├─► MCP 2: Target Class (타겟 분류)
            └─► MCP 3: OpenTargets Disease Association (질환 연관성)
            │
            ▼ 5. 지식 메모리(ResearchContext) 등록 (Priority 1)
```

#### 최근성 / 빈도 정렬

최근 등장 일자와 출현 횟수를 기준으로 내림차순하여 비교적 최근, 그리고 많이 언급된 유전자를 우선시하는 방식이다. 해당 방식은 기존의 치료법에 대한 논문을 최대한 제외하고 새로운 표적 제의를 하는 데 사용한 것으로 사료된다.

#### LLM 심사

LLM 심사는 다음과 같은 기준으로 동작하며, 자연어를 다루는 애매한 부분들을 담당한다:
- 사용자 질의 제약사항 부합성
- 검증 가치성
- 매칭 가능성 및 우선순위 저하 (deprioritized)
- 노이즈 및 비유전자 토큰 (drop)

다만 검증가치성이나 매칭 가능성, 우선순위 저하 등은 직접 DB를 조회하여 판단할 수 있는 기준들이므로 LLM의 역할은 제한적일 수 있다.

```
LLM 기반 사전 심사 결과 예시
{
  "selected": ["CXCR4", "IL6R", "JAK2", ...],   // 이번 회차에 실제 DB 검증할 상위 N개   "deprioritized": ["TP53", "MYC", ...],  // 검증을 미룰 유전자
  "drop": ["XYZ123", "NONGENE"]                 // 노이즈 및 비유전자 토큰
}
```

#### 생물학적 근거 기반 타겟 검증

이전 단계에서 "검증할만한" 유전자들에 대해 OpenTargets 등 외부 바이오 MCP API를 호출하여 3가지 핵심 생물학적 속성을 수집하고 검증한다.

1. GO CC: 생물학적 위치(Cellular Component)
2. OpenTargets / ChEMBL DB의 Target Class 분류체계
3. OpenTargets Disease Association: 질환 연관성(Disease Association)

이 부분에서 LLM에게 해당 정보들을 제공하고 LLM이 평가하도록 한다..

#### 왜 이렇게 설계하였을까?

모르겠다. 해당 부분은 OT 점수를 더 확인해봐야 알겠으나, OT의 association score는 텍스트 마이닝을 근거 유형 중 하나로 포함되기 때문으로 추정된다. 즉 많이 연구된 유전자일수록 점수가 높기 때문에 표적 가설 생성이라는 목적에 부합되지 않기 때문이라는 것이다.

다만, 생물학적 근거 기반 타겟 검증은 정량적으로 평가할만하지 않나?

## Origene과의 구조적 차이

OriGene은 후보 타겟 풀과 MCP 검증 데이터를 파이썬 세션 메모리(In-Memory)상에서만 유지하므로, 프로세스가 종료되면 가설 데이터가 모두 휘발된다.
반면, 본 L2 설계에서는 LLM 심사 및 MCP 생물학적 검증을 거친 타겟 가설과 3가지 핵심 근거 데이터를 영속 저장소(Persistent Store)에 구조화하여 저장함으로써, 가설의 재현성(Reproducibility), 근거 추적성(Traceability), 정량적 스코어링의 재사용성을 보장한다.

이를 위해 LLM 심사 단계와 생물학적 근거 타겟 검증 부분을 구조적으로 매핑한다.

## 전수 계산

Origene은 각 후보마다 iteration을 통해 탐색을 시도한다. 즉, 1개의 후보에 대해서 LLM을 통해 근거를 찾고, 이를 토대로 MCP를 실행한다. 따라서 후보에 따라 탐색 깊이의 차이가 발생하게 된다. 또한 각 후보마다 LLM을 호출하게 되므로 호출 비용도 만만치 않다.

또한 해당 방식은 가설 검증의 재현성을 확보한다. 같은 입력에 같은 결과값이 도출된다. 그러나 LLM의 창의성은 좀 덜한 편. 뿐만 아니라 결측치도 보인다는 점이 좋다. 해당 타겟 후보를 찾아보지 않은 것과, 찾았으나 근거가 부족하다는 것을 명시적으로 구분할 수 있다.

다만 한 후보를 집중적으로 반복하여 탐색하는 루프 분기를 설계할 필요성이 보인다.

해당 부분은 아직 검토해야할 사항이나 다음과 같은 구현 계획을 제안한다.

## Origene과의 구조 결합

```
1. 최근성/빈도 정렬 → shortlist
2. LLM 심사
   ├── drop           (영구 유효 사유로만 제한: 비유전자 토큰·식별자 오류)
   ├── deprioritized  (풀 복귀: 기존 메커니즘 유지)
   └── selected
        ↓
3. Pinning (_pinned_symbols)             (유지)
        ↓
4. 생물학적 검증  (MCP 3속성 → OT 16인자 + 추가 2건으로 확장 + 스냅샷 기록)
        ↓
5. ResearchContext → B 원장 연결
```
 
`deprioritized` 후보에도 OT 조회는 수행한다. 벌크 조회라 후보 수와 무관하게 비용이 거의 같고, 그래야 다음 회차 재심사에 근거가 있으며 근거 갱신 시 트리거가 걸린다.

## 생물학적 검증

**OpenTargets-MCP**를 활용하여 두 종류의 근거 구조를 정립한다
- Association Evidence(질환 특이적 성격): 유전자와 질병의 연관성에 대한 근거.
- Target Prioritisation(질환 비종속 성격): 표적의 작업 가능성

추가적으로 근거 구조를 추가한다
- cis-MR + colocalization: 특징 유전자/단백질과 질환의 인과적 원인(Causal Target) 확인
- 임상 실패 사유: 해당 타겟에 대한 임상 시험이 실패한 사유.

### Associate Evidence

| 유형 | 내용 |
|---|---|
| Genetic association | GWAS·희귀변이 기반 질환 연관 |
| RNA expression | 질환 조직 발현 변화 |
| Literature (text mining) | 문헌 공출현 |
| Animal model | 모델 표현형 |
| Known drug | 임상 전례 |
| Affected pathway | 경로 관여 |

### Target Prioritisation

전부 명시적 정의, 점수 규칙이 문서화되어 있고 Open Targets가 계산해 배포한다.
녹색=긍정, 적색=부정의 신호등 표시까지 설계되어 있다.

#### Precedence (우선순위)

| 인자 | 정의 | 점수 |
|---|---|---|
| **Target in clinic** | 적응증 무관, 이 표적을 겨냥한 약물의 최대 임상 단계 | 0.01(전임상) ~ 1.0(승인/4상/철회) |

#### Tractability (약물 개발 용이성)

| 인자 | 출처 | 점수 |
|---|---|---|
| Membrane protein | HPA + UniProt | 1 / 0 / NA |
| Secreted protein | HPA + UniProt (충돌 시 HPA 우선) | 1 / 0 / NA |
| Ligand binder | ChEMBL 고품질 리간드 | 1 / 0 / NA |
| Small molecule binder | PDB 공결정 | 1 / 0 / NA |
| Predicted pockets | DrugEBIlity ≥ 0.7 | 1 / 0 / NA |

### Doability

| 인자 | 출처 | 점수 |
|---|---|---|
| Mouse ortholog identity | Ensembl Compara | 80% 이상 유사도 → 0~1 선형 |
| Chemical probes | Probes & Drugs | 1 / 0 / NA |

### Safety

| 인자 | 출처 | 점수 |
|---|---|---|
| Genetic constraint | gnomAD **LOEUF** 순위 | −1(LoF 비관용) ~ 1(관용) |
| Mouse models | MGI KO 표현형, **기관계별 중증도 가중** (간/심혈관/사망 −1, 신경/호흡/신장 −0.75 …) | 0 ~ −1 |
| Gene essentiality | DepMap common essential | −1 / 0 / NA |
| Known safety events | OT Safety + ClinPGx | −1 / NA |
| Cancer driver gene | COSMIC (종양억제/암유전자) | −1 / NA |
| Paralogues | Ensembl, 60% 이상 유사체 | 0 ~ −1 |
| Tissue specificity | GTEx + Tabula Sapiens, CELLEX ESmu | 1 ~ −1 |
| Tissue distribution | GTEx + Tabula Sapiens, 발현 조직 비율 | 1 ~ −1 (편재 발현이 −1) |

### cis-MR + colocalization
 
```
OT 제공     "이 유전자는 RA와 연관"
없는 것      "올려야 하나 내려야 하나"  → dir 결정 불가
            "연관이 인과인가"          → 교란·역인과 구분 불가
```
 
**`dir`(억제/작용)이 개발 양식을 결정한다.** 방향 없는 표적 가설은 불완전하다.
 
#### 표준 cis-MR
 
- 표적 유전자 **근방(cis) 변이만** 도구변수로 사용
- cis 변이는 trans보다 **다면발현 가능성이 낮음** (Schmidt et al. 2020)
- 노출 = 발현량(eQTL) 또는 단백질 수준(pQTL), 결과 = RA 위험(GWAS)
- **Colocalization 병행 필수** — MR 신호와 GWAS 신호가 같은 인과 변이를 공유하는지 확인. 안 겹치면 LD에 의한 허위 연관 가능

#### 근거 강도
 
개발 약물 268건 후향 평가에서, **단백체 MR과 coloc 지지를 모두 받은 표적-적응증 쌍의 성공 오즈비 26.4** (95% CI 4~580).
 
> 신뢰구간이 넓어 정밀하진 않으나, 일반 유전학 근거의 2.6배(Minikel 2024)보다 강한 신호다.

### 임상 실패 사유

실패 사유에 따라 같은 Precedence 점수의 의미가 정반대가 된다. 따라서 사용을 하는 것을 추천하나, 해당 데이터는 찾기도 힘들고 생성하는 것도 위험하다. 왠만하면 구현은 일단 미루고, P2-L3 단계에서 검증 후 다시 논의.

## 후보물질 순위 산출 방식 비교

### 1. 기존 구성 (OriGene 통계 기반 정렬)

OriGene은 후보 풀 내 타겟 유전자들의 순위를 계산할 때 결정론적 통계 정렬 키(`-last_seen`, `-count`, `-len(sources)`)를 사용합니다.

* **산출 메커니즘**:
  1. **최근성 (`last_seen`)**: 가장 최근 탐색 회차(Iteration)에 등장한 유전자를 1순위 배치
  2. **출현 빈도 (`count`)**: 문헌 검색 및 도구 실행 결과 텍스트 내 등장 횟수가 많은 유전자를 2순위 배치
  3. **출처 다양성 (`len(sources)`)**: 서로 다른 검색 도구(Tavily, PubMed 등)에서 공통 발견된 유전자를 3순위 배치
* **장점**:
  - 구현이 매우 간단하고 연산 비용이 전혀 들지 않음
  - 최근 이슈가 되고 여러 도구에서 공통 언급된 유전자를 직관적으로 상위에 노출
* **한계점**:
  - **논문 빈도 편향 (Popularity Bias)**: 이미 수만 편의 논문이 출판된 기존 구형 타겟(`TNF`, `IL6`, `TP53` 등)이 항상 상위권을 독점하여 신규 표적(Novel Target) 발굴 가능성이 저하됨
  - **생물학적 타당성 미반영**: 단순 언급 횟수일 뿐, 표적의 실제 인과성(MR), 약물화 가능성(Tractability), 안전성 리스크(Safety)가 순위에 전혀 반영되지 않음

### 2. 제안 구성 (OpenTargets + cis-MR 정량 스코어링)

새로 제안하는 방식은 OpenTargets 16개 핵심 평가 인자와 cis-MR/colocalization 분석 수치를 결합한 정량적 종합 점수($S_{\text{target}}$)를 산출하여 순위를 계산합니다.

* **산출 메커니즘**:
  $$S_{\text{target}} = w_{\text{assoc}} \cdot S_{\text{Assoc}} + w_{\text{prec}} \cdot S_{\text{Precedence}} + w_{\text{tract}} \cdot S_{\text{Tractability}} + w_{\text{doab}} \cdot S_{\text{Doability}} + w_{\text{causal}} \cdot S_{\text{Causal}} + S_{\text{Safety Penalty}}$$
  1. **질환 연관성 ($S_{\text{Assoc}}$)**: OpenTargets 6개 영역 연관성 통합 점수 (0.0 ~ 1.0)
  2. **약물 개발 용이성 ($S_{\text{Tractability}}$)**: 막단백질/분비단백질/리간드 결합 등 5개 약물화 지표 합산
  3. **인과 추론 점수 ($S_{\text{Causal}}$)**: cis-MR 효과 크기($|\beta|$)와 Colocalization 신뢰도($H_4$)의 곱
  4. **안전성 감점 ($S_{\text{Safety Penalty}}$)**: gnomAD LOEUF, 마우스 KO 표현형 중증도, 타겟 조직 편재성에 따른 감점 적용
* **장점**:
  - **신규 유망 표적 부상**: 문헌 언급 횟수가 적더라도 인과성과 약물화 가능성이 높은 신규 타겟을 상위에 배치
  - **생물학적 타당성 및 재현성 확보**: 동일 바이오 DB 데이터 입력 시 100% 동일한 수치 점수가 계산되어 영속 저장소(L2 DB)에 정량 저장 및 비교 쿼리 가능
* **고려사항**:
  - OpenTargets 및 cis-MR 데이터 조회/계산 연산이 추가되어 프로토타입 개발 초기 단계에서 가중치 튜닝 필요

## L2 아키텍처 한계 및 도메인 특화(류마티스군 질환) 설계 당위성

### 1. 현 L2 아키텍처의 내재적 한계 (Scope & Input Constraints)

본 L2 아키텍처는 OriGene의 범용성을 일부 제한하고 특정 규격을 강제함으로써 발생하는 명확한 내재적 한계를 지닌다.

1. **입력 타겟 규격의 고정 (HGNC Protein-coding Gene 전제)**
   - OpenTargets 16개 인자, LOEUF, DepMap, cis-MR(eQTL/pQTL) 검증 수식은 모두 **단백질 부호화 유전자(Protein-coding Gene)**를 전제로 설계되었다.
   - ncRNA, 미생물 표적, 세포 치료제, non-protein target 등 비단백질 표적 가설은 정량 스코어링 수식으로 평가할 수 없다.
2. **도메인 데이터 의존성 (GWAS/eQTL 데이터 필수성)**
   - cis-MR 및 Colocalization 분석은 대규모 바이오뱅크 및 유전체 보조 데이터셋이 축적된 질환에서만 구동 가능하다.
   - GWAS 데이터셋이 없거나 보조 데이터가 부족한 희귀질환 및 신종 감염병 도메인에서는 정량 인과 추론 모듈이 무효화된다.
3. **단일 표적 직접 개입 가설로의 한정 (Direct Target Modulation)**
   - "유전자 A를 직접 억제/작용(`dir`)한다"는 1차 개입 가설만을 평가하므로, 다중 표적(Multi-target) 조합 또는 콤비네이션 기전 평가에는 제약이 따른다.

---

### 2. 류마티스군 질환(RA/PsA) 표적 발굴을 위한 아키텍처 설계 당위성

위와 같은 한계에도 불구하고, **류마티스 관절염(RA) 및 건선성 관절염(PsA) 등 근골격계 염증성 질환 표적 발굴**이라는 목표를 달성하기 위해 본 구조를 채택한 정당한 근거와 논리는 다음과 같다.

#### 1. OriGene의 범용적 LLM 정성 반증(Critic) 한계 극복
OriGene은 범용성을 유지하기 위해 LLM의 텍스트 비평(Critic)에만 반증을 의존하였다. 그러나 염증성 질환 표적은 면역 억제에 따른 **감염/종양 발생 리스크(Safety)** 및 **약물 접촉 가능성(Tractability)**이 정량적으로 검증되어야만 전임상 단계 진입이 가능하다. 따라서 OpenTargets Safety DB 및 LOEUF 지표를 정량 수식에 직접 연결하는 구조가 필수적이었다.

#### 2. 류마티스 도메인의 유전체/단백체 데이터 자산 활용 최적화
류마티스 관절염은 바이오의약품 개발 역사상 GWAS, eQTLGen, UK Biobank pQTL, OpenTargets Platform 데이터가 **가장 잘 정비되어 있는 1군 질환 도메인**이다. 도메인 특화 데이터 자산이 풍부한 영역이므로, 데이터가 부족할 때 쓰이는 "범용 탐색 방식(OriGene)" 대신 **"대규모 유전학 데이터 기반 cis-MR + Coloc 정밀 인과 추론 구조"**를 채택하는 것이 가설의 신뢰도(Confidence Level)를 극대화하는 가장 논리적인 선택이다.

#### 3. 개입 방향성(`dir`: 억제 vs 작용) 미결정 문제의 완전 해결
기존 OpenTargets 연관성 점수(Association Score)는 "유전자 A가 RA와 연관됨"만을 알려줄 뿐, "신약으로 유전자 A를 올려야 하는지 내려야 하는지" 방향성을 결정해주지 못한다. 본 L2 아키텍처에 **cis-MR Effect Size ($\beta$) 및 Coloc ($H_4$)**을 필수 결합함으로써, **약물 개발 양식(Agonist vs Antagonist)을 명확히 결정**할 수 있는 검증 가설을 완성하였다.

#### 4. 결정론적 재현성 및 L2 영속 저장소(Persistent DB) 매핑
OriGene은 탐색 결과가 파이썬 RAM에만 남아 프로세스 종료 시 소멸하는 구조적 한계가 있었다. 입력 스키마와 정량 스코어링 수식을 고정함으로써, **동일 입력에 대한 100% 재현 가능한 정량 점수($S_{\text{target}}$) 및 팩트 근거 데이터**를 L2 영속 저장소에 구조화하여 저장하고 L3/L4 에이전트로 손실 없이 전달할 수 있게 설계하였다.
