## 1. 목표와 목적

### 1.1 배경

신약개발은 유전체, 전사체, 단백체 등 오믹스(Omics) 데이터의 폭발적인 증가와 자연어 처리(NLP) 기술의 발전으로 인해 혁신적인 변화의 시기를 맞고 있다. 후보 물질의 in-silico 가설 생성은 연구자가 문헌을 검색, 데이터베이스 조회 및 약물성 검토를 반복적으로 수행하는 구조이다. 해당 부분을 에이전트가 담당함으로써 후보 생성과 우선순위화 병목을 줄이고, 이를 통해 후속 검증 단계에 투입되는 후보 수와 비용을 최소화하는 것이 해당 프로젝트의 배경이다.

RA/PsA 파이프라인은 75~100개 이상 기업이 경쟁할 만큼 활발하고 시장 규모도 크다(2026년 기준 RA 약 $28~39B, PsA 약 $11~14B). 그러나 새로 나오는 치료제도 대부분 이미 검증된 표적(TNF/IL-6/IL-17/IL-23/JAK/TYK2) 안에서의 변주에 그쳐, 근골격계 증상 완전 조절 같은 미충족 수요가 여전히 남아있다.

신약개발 초기 단계에서 후보 하나당 근거를 모으는 비용은 상당하다. 조직 발현·유전학·성약성·시험 이력·안전성을 모두 확인하려면 숙련자가 후보당 며칠씩 걸리므로, 실제로는 3~5개만 검토하고 300개는 못 본다. 그 결과 선택이 친숙도에 지배되고, 후보마다 조사 깊이가 달라 비교가 불가능해지며, 반박 근거는 거의 수집되지 않는다. 이를 해결하기 위해 Agent가 담당하여 후보 생성과 우선순위화 병목을 줄이고, 이를 통해 후속 검증 단계에 투입되는 후보 수와 비용을 최소화하는 것이 해당 프로젝트의 목적이다.

### 1.2 목적

문헌 검색, 오믹스데이터와 지식그래프 설계 및 구축 등 파편화된 정보들을 통합해, RA에 대한 신규 치료 표적 후보 가설을 자율적으로 생성하고 근거 기반으로 검증하는 사이클을 개발한다. 연구진에게는 **"사람의 대체가 아닌 보조 도구"**로서 작동한다.

### 1.3 목표

- 근거기반성(Evidence Groundedness): 생성되는 모든 가설과 그 검증 과정은 연구자가 검증할 수 있도록 추적 가능한 문헌과 데이터 출처로 뒷받침되어야 한다.
- 신규성(Novelty): 기존 데이터베이스(ChEMBL, OpenTargets 등)에 해당 질환과 명시적으로 연관되지 않은 타겟과 재창출 후보를 발굴해야 한다.
- 설명가능성(Explainability/Traceability): 가설에 이르는 추론 사슬, 근거, 한계점 등이 사람 전문가가 검토할 수 있는 형태로 제시되어야 한다.

이에 대한 평가 지표는 다음과 같다:

| 지표 | 정의 | 측정 지점 |
|---|---|---|
| 인용 근거 정확성 | 에이전트가 제시한 근거 문헌이 실제로 해당 주장을 지지하는지 비율 | Evidence Audit Gate (§3.2.5) · S7 (§4.3) |
| 신규성 비율 | 기존 데이터베이스 대비 새롭게 제안된 타겟·재창출 후보의 비율 | 후보 열거 단계의 신규성 메타 |
| 전문가 동의율 | 사람 전문가 검토에서 "타당하다"고 평가되는 가설의 비율 | Human Review Gate (§3.2.4) · 측정 설계는 §4.4 (검토 중) |

세 지표 모두 별도의 측정 장치를 새로 만들지 않고, 파이프라인이 정상 동작하면서 자연히 남기는 기록에서 산출한다.

### 1.4 범위

| | 포함 | 제외 |
|---|---|---|
| **단계** | 표적 발굴 (in-silico 가설 생성) | 히트 발굴, 리드 최적화, 임상 설계 |
| **질환** | **RA 단독** | PsA·AS·OA·Gout (후속 확장) |
| **표적 유형** | HGNC 단백질 부호화 유전자 | ncRNA, 미생물 표적, 세포치료제 |
| **개입 형태** | 단일 표적 직접 개입 (`dir` = 억제/작용) | 다중 표적 조합 |
| **검증** | in-silico 근거 조립 | wet-lab 실험 (인간 연구자에 위임) |
| **산출** | 순위화된 가설 카드 + 판정 메모리 | 화합물, 실험 프로토콜 |


## 2. 용어

### 2.1 RA 관련

- **류마티스 관절염(RA)**: 면역계가 자기 관절 조직을 공격하는 자가면역질환. TNF-α·IL-6·IL-17·JAK 등 명확한 분자 타겟과 승인 치료제가 다수 존재해 화합물-활성 데이터가 풍부하다.
- **활막(Synovium)**: 관절강을 둘러싼 조직. RA 염증의 병변 부위이며 생검 기반 분자 프로파일링이 확립되어 있다.
- **병리형(Pathotype)**: 활막 면역세포 조성 분류 — lymphomyeloid / diffuse-myeloid / fibroid. R4RA·STRAP 등 생검 기반 시험에서 사용. 본 문서에서는 해당 시험 데이터를 설명하기 위한 배경 용어이며, 현재 스코프에서 표적 순위화에 직접 반영되지는 않는다.
- **불충분 반응**: 첫 TNF 억제제에 충분히 반응하지 않는 환자가 대략 3분의 1 수준으로 보고된다.

### 2.2 신약개발 방법론 관련

- **표적 발굴 vs 히트 발굴**: 전자는 "무엇을 겨냥할 것인가", 후자는 "그 표적에 결합하는 화합물". **본 프로젝트는 전자에 한정.**
- **성약성(Tractability)**: 표적에 약물이 접근 가능한가 — 세포외·막관통 여부(항체), 결합 포켓 유무(소분자).
- **cis-MR**: cis-MR은 어떤 표적을 증가시키거나 감소시키는 것이 질병에 유리할 가능성이 있는지를 보여준다. 그러나 그 결과가 실제 약물의 투여 조직, 기간, 용량에 따른 작용과 완전히 같다고 보지는 않는다.
- **Colocalization**: 질환 GWAS와 분자 QTL이 동일 인과 변이를 공유하는지 검정. MR과 병행하지 않으면 LD에 의한 허위 연관을 배제할 수 없다.
- **LOEUF**: gnomAD의 유전자별 loss-of-function 관용도. 낮을수록 LoF 비관용 — 필수성·안전성 대리 지표.
- **Three Pillars**: 신약 개발 및 신뢰성 있는 임상시험 수행을 위해 정립한 '생존의 세 가지 기둥(Three Pillars of Survival)' 모델을 의미한다.
    1. 노출: 약물이 인체 내 Target(표적)이 존재하는 조직이나 세포까지 충분한 농도로, 필요한 시간 동안 도달했는가?
    2. 결합: 목적지에 도달한 약물이 실제로 해당 표적 단백질에 제대로 결합(점유)했는가?
    3. 기능적 약리: 약물이 표적에 결합하여, 의도했던 생물학적/약리학적 반응 및 하위 신호전달 변화를 실제로 유도했는가?

    **반증의 성립 조건은 "세 번째 기둥에서 실패했는가"가 아니라 "세 기둥이 모두 충족되었는가"이다.** 노출·결합이 확인되지 않은 실패는 약물·시험 설계의 문제이므로 표적 가설의 반증으로 해석하지 않는다. 기능적 약리가 관찰되지 않은 경우도 그 자체로는 반증이 아니다 — 바이오마커 선택 부적절, 표적 조절 수준 미달, 평가 시점 부적절, 조직·환자군 특이적 발현, 측정 민감도 부족 등 다른 설명이 열려 있기 때문이다.

    반증이 성립하는 것은 **충분한 노출·표적 결합·의도한 기능적 약리가 모두 확인되었음에도 적절한 환자군의 임상 평가에서 효능이 나타나지 않은 경우**이며, 이때 반증되는 것은 표적 단독이 아니라 **표적–개입 방향–환자 맥락의 결합 가설**이다. 이 구분은 Critic의 임상 실패 해석 규칙(§3.2.2)에 그대로 적용된다.

    > **실무상 대부분은 판정 불가다.** 세 기둥 귀속에는 PK·표적 점유·약력학 바이오마커 데이터가 필요한데 공개 임상 기록 다수에는 존재하지 않는다(§3.4의 임상 실패 사유 커버리지 문제와 같은 뿌리). 따라서 Critic은 `귀속_불가`를 정상적인 결과 상태로 갖는다.
- **분자 도킹 / ADMET / SMILES**: 화합물의 결합력·약물 유사성·구조 계산 기법. 후속 트랙.

### 2.3 Agent 관련

- **지식그래프**: 유전자·질병·약물 등 개체와 관계를 그래프로 표현한 DB. 새로운 연결고리 탐색에 사용.
- **ReAct**: think → act → observe 반복으로 다음 행동을 스스로 정하는 패턴. **L2 후보 탐색 루프**(§3.2.1)가 해당.
- **Reflection**: 생성자가 산출물을 내고 비판자가 반박한 뒤 수정하는 루프. **L3 가설 정련 루프**(§3.2.2)가 해당.
- **벌크 기저**: 전 후보에 동일하게 깔리는 근거 집합. 비용이 후보 수와 무관해 전수 확보하며, 탐색이 백지에서 시작하지 않게 한다.
- **탐색 이력**: 후보별 탐색의 각 단계(판단·호출·결과·근거 버전) 기록. 재방문 시 재개의 근거.
- **결정 원장**: 사람의 판정을 사유 코드·근거 버전과 함께 append-only로 남기는 저장소.
- **근거 버전 고정**: 각 판정이 어느 스냅샷에 기반했는지 못박는 것. 없으면 "이 판정이 지금도 유효한가"에 답할 수 없다.
- **차분 엔진**: 근거 갱신 시 영향받는 판정만 재검토 큐에 되돌리는 장치.


## 3. 전체 아키텍처 개요

해당 아키텍처는 ReAct Framework를 기반으로 설계되었다.
가설 생성과 반증을 통해 후보를 발굴하고, 해당 후보에 대한 검증 가설을 수립하는 과정을 거친다.

[전체 아키텍처](./images/full_system_architecture.svg)

### 3.1 계층 구성

| 계층 | 역할 | 성격 |
|---|---|---|
| L1 수집 | 소스별 스냅샷 확보·버전 고정 | 결정론적 |
| L2 생성 | 후보 열거 → 심사 → 벌크 기저 → 후보별 ReAct 탐색 | 에이전트 |
| L3 정련 | 명제 구성 ↔ 반증 수집 (**Reflection**) → 카드 | 에이전트 |
| L4 원장 | 사람 판정을 사유 코드·근거 버전과 함께 append-only 기록 | 기록·버전 체인은 결정론적 (판정 자체는 사람) |
| L5 차분 엔진 | 근거 갱신 감지 → 영향 판정 **식별** → 재검토 큐 | 식별은 결정론적 (해석은 L2·L3·사람) |

> **"결정론적"의 범위를 정확히 한다.** L4에서 결정론적인 것은 판정을 저장하고 버전 체인을 구성하는 절차이지 사람의 채택·기각 판단이 아니다. L5에서 결정론적인 것은 두 스냅샷 비교, 변경 필드 식별, 해당 근거를 참조한 판정 조회, 재검토 큐 구성까지다. **변경이 명제와 판정에 어떤 의미를 갖는지에 대한 해석은 결정론적일 수 없으며, L2·L3와 사람 검토에 위임한다.**

### 3.2 루프 구조

본 시스템은 표적 후보의 근거를 반복적으로 수집하고 가설을 정련하며, 이후 새로운 근거가 추가되었을 때 기존 판정을 갱신하기 위해 세 개의 핵심 루프를 사용한다.

#### 핵심 객체 관계

루프를 설명하기 전에, 루프가 다루는 객체와 그 연결 구조를 고정한다. **명제 단위 추적(§3.2.6 원칙 4)과 의존 근거 필드(§3.3.3)가 왜 필요한지는 이 구조에서 나온다.**

```text
후보 (Candidate)  — HGNC 유전자 1개
   └─ 가설 (Hypothesis)  — 후보 + 개입 방향(dir) + 맥락(조직·환자군)
         └─ 명제 (Proposition) × 6  — 검토 가능한 최소 단위
               ├─ 지지 근거 (Evidence⁺)  ─┐
               └─ 반박 근거 (Evidence⁻)  ─┤  각 근거는 소스·스냅샷 버전을 가짐
                                          │
                                    판정 (Decision)
                                          └─ 의존 근거 필드 = 참조한 Evidence 집합
```

| 관계 | 의미 |
|---|---|
| 후보 : 가설 | 1 : N — 같은 유전자에 대해 억제 가설과 활성화 가설이 별도로 존재할 수 있다 |
| 가설 : 명제 | 1 : 6 — 명제 집합은 고정 (§3.2.2) |
| 명제 : 근거 | 1 : N — 지지·반박을 분리 저장 |
| 판정 : 근거 | N : M — 판정이 참조한 근거를 역방향 조회 가능하게 기록 |

**근거 갱신의 파급 범위가 이 그래프를 타고 결정된다.** 어떤 근거 항목이 변경되면 그 근거에 연결된 명제만 재평가되고(`REOPEN_L3`), 명제 자체가 새로 필요해지면 후보 탐색으로 되돌아간다(`REOPEN_L2`). 명제 단위로 근거를 붙이지 않으면 이 구분이 불가능해 매번 후보 전체를 다시 돌려야 한다.

#### 세 루프의 역할

각 루프는 서로 다른 목적과 시간 범위를 가진다.

| 루프 | 위치 | 목적 | 실행 주기 |
|---|---|---|---|
| **후보 탐색 루프** (ReAct) | L2 | 후보별 근거 공백을 식별하고 필요한 근거를 추가 수집 | 단일 실행 내 반복 |
| **가설 정련 루프** (Reflection) | L3 | 후보 가설을 명제로 분해하고 반증을 반영하여 수정·축소·기각 | 후보 카드별 반복 |
| **판정 재검토 루프** | L5 | 새로운 근거가 기존 가설이나 판정에 미치는 영향을 추적하여 필요한 부분만 재실행 | 근거 갱신 시 실행 |

세 루프는 독립적으로 동작하지 않는다. 가설 정련 과정에서 추가 근거가 필요하면 후보 탐색 루프로 되돌아가며, 새로운 근거가 유입되면 판정 재검토 루프가 영향 범위에 따라 L2 또는 L3를 다시 실행한다.

```text
후보 탐색(L2)
      ↓
가설 정련(L3)
      ├─ 판정 가능 → 사람 검토 및 원장 기록
      └─ 추가 근거 필요 → 후보 탐색(L2)으로 반환

새로운 근거 유입
      ↓
판정 재검토(L5)
      ├─ 순위만 영향 → 재순위화
      ├─ 명제에 영향 → 가설 정련(L3) 재개
      ├─ 추가 분석 필요 → 후보 탐색(L2) 재개
      └─ 구조적 변경 → 전체 파이프라인 재실행
```

#### 3.2.1 후보 탐색 루프 — Evidence Exploration Loop

후보 탐색 루프는 후보별 근거를 동일한 깊이로 무조건 수집하는 과정이 아니다. 현재 확보된 근거를 평가하고, 후보의 판정이나 순위에 가장 큰 영향을 줄 수 있는 근거 공백을 우선적으로 조사하는 ReAct 기반 탐색 과정이다.

기본 흐름은 다음과 같다.

```text
현재 근거 상태 확인
        ↓
핵심 근거 공백 식별
        ↓
도구 및 질의 선택
        ↓
근거 수집·정규화
        ↓
근거 품질·중복·상충 여부 확인
        ↓
후보 점수 및 불확실성 갱신
        ↓
탐색 계속 또는 종료
```

탐색 대상이 되는 주요 근거 축은 다음과 같다.

* RA 질환 연관성
* 활막 및 관련 세포 유형에서의 발현·활성
* 유전학적·인과적 근거
* 개입 방향
* 성약성
* 안전성 위험
* 기존 임상시험 및 실패 이력
* 가설을 반박하는 주요 근거

모든 후보에 동일한 탐색 비용을 투입하지 않는다. 초기 근거가 충분하고 불확실성이 낮은 후보에는 제한된 탐색을 수행하고, 신규성이 높거나 근거 간 충돌이 큰 후보에는 심층 탐색을 수행한다.

| 탐색 상태 | 의미 |
|---|---|
| `EXPLORE_SHALLOW` | 기본 근거 확인을 위한 제한적 탐색 |
| `EXPLORE_DEEP` | 상충 근거·높은 신규성·높은 불확실성으로 인한 심층 탐색 |
| `HOLD_DATA` | 핵심 데이터가 없어 현재 판단 불가능 |
| `COMPLETE` | 필요한 근거 조사가 완료된 후보 |

> 범위 밖 후보(`DROP_SCOPE`)는 탐색 루프의 상태가 아니라 **Prescreener가 루프 진입 이전에 처리한다.** 탐색 비용을 쓰기 전에 걸러내는 것이 목적이므로, 루프 내부에서 같은 판정을 반복하지 않는다.

탐색은 다음 중 하나를 만족할 때 종료한다.

1. 필수 근거 축의 조사가 완료된 경우
2. 남은 근거 공백이 명시되었으며 현재 도구로 해결할 수 없는 경우
3. 추가 탐색이 후보의 순위나 판정을 변경할 가능성이 낮은 경우
4. 동일하거나 중복된 근거가 반복적으로 검색되는 경우
5. 후보별 호출 예산이 소진된 경우

종료 시에는 근거가 충분해서 종료된 경우와 데이터·예산 부족으로 종료된 경우를 구분하여 기록한다. **이 구분이 §3.7 내재적 한계 4(커버리지 비결정성)를 정량화하는 수단이 된다** — 후보별 심화 근거가 균일하지 않다는 사실 자체를 숨기지 않고 종료 사유 분포로 노출한다.

> 종료 조건 3과 5는 에이전트의 판단·예산에 의존하므로 실행마다 탐색 경로가 달라질 수 있다. 이는 §4.3 S6과 충돌하지 않는다 — **S6이 요구하는 것은 최종 근거 값의 재현성이지 탐색 경로의 재현성이 아니다**(§3.3.4).

#### 3.2.2 가설 정련 루프 — Hypothesis Refinement Loop

가설 정련 루프는 Explorer가 수집한 근거를 바탕으로 Analyst가 표적 가설을 구성하고, Critic이 해당 가설의 약한 가정과 반증 근거를 검사하는 Reflection 과정이다.

표적 가설은 하나의 포괄적인 문장으로만 평가하지 않고, 검토 가능한 하위 명제로 분해한다.

예를 들어 특정 표적을 억제하는 RA 치료 가설은 다음과 같은 명제로 구성될 수 있다.

1. 해당 표적은 RA 병태생리에 관여한다.
2. 해당 표적의 작용은 RA 병변 조직 또는 관련 세포에서 나타난다.
3. 표적을 제안된 방향으로 조절하면 질병 관련 기능이 감소할 가능성이 있다.
4. 표적은 제안된 약물양식으로 접근할 수 있다.
5. 허용 가능한 안전성 범위가 존재할 가능성이 있다.
6. 기존 임상시험 및 반증 근거가 가설을 결정적으로 부정하지 않는다.

각 명제에는 지지 근거와 반박 근거를 별도로 연결하고, 근거 상태를 다음과 같이 구분한다.

| 명제 상태 | 의미 |
|---|---|
| `SUPPORTED` | 직접적이고 비교적 일관된 지지 근거가 존재 |
| `PARTIAL` | 제한적이거나 간접적인 근거만 존재 |
| `CONFLICTED` | 지지 근거와 반박 근거가 공존 |
| `REFUTED` | 핵심 반증이 지지 근거보다 우세 |
| `UNKNOWN` | 판단에 필요한 근거가 부족 |

> **"근거 부족"을 나타내는 상태가 세 층위에 각각 존재한다.** 혼동을 피하기 위해 관계를 다음과 같이 고정한다.
>
> `UNKNOWN`(명제 수준) → 해당 명제 하나만 판단 불가
> `INDETERMINATE`(가설 수준) → 핵심 명제가 `UNKNOWN`·`CONFLICTED`여서 가설 전체의 권고를 낼 수 없음
> `HOLD_DATA`(후보 수준) → 필수 근거 축 자체가 비어 있어 명제 구성 단계에 진입하지 못함

Critic은 단순히 반대 의견을 생성하는 역할이 아니라 다음을 검사한다.

* 다른 질환의 근거를 RA에 과도하게 전이하지 않았는가
* 발현 연관성을 질병 구동 인과성으로 해석하지 않았는가
* 유전적 방향을 실제 약물작용과 동일시하지 않았는가
* **임상 실패를 Three Pillars(§2.2)로 귀속했는가** — 아래 귀속 규칙에 따른다
* 특정 조직·세포·환자군에서만 성립하는 가설을 전체 RA에 일반화하지 않았는가
* 안전성이나 필수성 근거가 누락되지 않았는가

**임상 실패 귀속 규칙.** Critic은 확인된 임상 실패 각각에 대해 다음 중 하나를 부여한다.

| 귀속 상태 | 조건 | 반증 효력 |
|---|---|---|
| `PILLAR_미충족` | 노출 또는 표적 결합이 확인되지 않음 | 없음 — 약물·시험 설계의 문제 |
| `약리_미확인` | 표적 결합은 확인되었으나 의도한 기능적 약리가 관찰되지 않음 | 약함 — 바이오마커·조절 수준·평가 시점 등 대안 설명이 열려 있음. 명제를 `CONFLICTED`로 전이시키되 `REFUTED`로 보내지 않는다 |
| `PILLAR_전부충족_무효능` | 노출·결합·기능적 약리가 모두 확인되었음에도 임상 효능 없음 | **강함** — 표적–개입 방향–환자 맥락 결합 가설에 대한 반증 |
| `귀속_불가` | 세 기둥 판정에 필요한 데이터가 공개되지 않음 | 없음 — 근거 부재를 반증으로 오독하지 않는다 |

> **`귀속_불가`가 다수 사례가 될 것으로 예상한다.** 세 기둥 귀속에는 PK·표적 점유·약력학 바이오마커가 필요한데 공개 임상 기록 다수에 존재하지 않는다(§3.4). 따라서 Critic이 실제로 수집하는 반증은 임상 실패 귀속보다 **인과 분석 방향 상충**과 **부정 결과 문헌**이 주를 이룬다. §4.2에서 Critic 제거의 효과를 해석할 때 이 구성을 감안한다.

Critic의 검토 결과에 따라 가설은 다음과 같이 분기된다.

| 분기 | 의미 |
|---|---|
| `MAINTAIN` | 핵심 가설 유지 |
| `REVISE` | 표현, 근거 강도 또는 조건 수정 |
| `NARROW_CONTEXT` | 특정 조직·세포·환자군으로 가설 범위 축소 |
| `FLIP_DIRECTION` | 억제·활성화 방향 재검토 |
| `REQUEST_EVIDENCE` | 추가 근거 수집 필요 |
| `REJECT` | 핵심 가정과 양립할 수 없는 반증 존재 |
| `INDETERMINATE` | 근거 부족 또는 충돌로 판단 보류 |

> `FLIP_DIRECTION`은 cis-MR로 `dir`이 이미 확정된 후보에서는 단순한 방향 수정이 아니라 **유전적 인과 근거와의 상충 신호**로 취급한다. 이 경우 방향을 바꾸기 전에 MR 추정의 타당성(도구변수 강도, coloc 결과)을 먼저 재확인하고, 상충이 해소되지 않으면 명제 상태를 `CONFLICTED`로 유지한다.

추가 근거가 필요하면 Critic은 직접 무제한 검색을 수행하지 않고 근거 요청을 생성하여 L2 Explorer로 반환한다.

```text
challenged_claim
required_evidence_type
expected_decision_impact
preferred_tool
priority
```

L2와 L3 사이의 무한 반복을 방지하기 위해 후보별 왕복 횟수와 총 호출 예산을 제한한다. 제한 내에서도 결론을 내릴 수 없는 후보는 `INDETERMINATE` 상태로 사람 검토에 이관한다.

가설 정련 루프의 최종 산출은 다음 네 가지 권고 상태 중 하나이다.

* 채택 권고
* 조건부 채택
* 보류
* 기각 권고

해당 권고는 최종 결정이 아니며, 연구자의 검토를 위한 구조화된 판단 자료로 사용한다. **권고 상태 어휘는 Human Review Gate(§3.2.5)에서 연구자가 사용하는 판정 어휘와 동일하게 맞춘다(§3.2.5)** — 두 값을 같은 척도로 비교해야 전문가 동의율(§1.3)을 별도 설문 없이 산출할 수 있다.

#### 3.2.3 판정 재검토 루프 — Evidence Update and Re-evaluation Loop

판정 재검토 루프는 새로운 문헌, 데이터베이스 릴리스, GWAS·QTL 결과, 임상시험 결과 또는 안전성 정보가 추가되었을 때 기존 판정의 유효성을 다시 평가한다.

모든 근거 변경이 전체 파이프라인의 재실행을 의미하지는 않는다. Differ는 변경된 근거가 어떤 후보와 명제에 연결되어 있는지를 추적하고, 영향 범위에 따라 재실행 수준을 결정한다.

```text
새 근거 또는 데이터 버전 감지
        ↓
이전 스냅샷과 차이 계산
        ↓
영향받는 후보·명제·판정 식별
        ↓
변경 영향도 분류
        ↓
필요한 수준만 재실행
```

> 위는 루프 관점의 개요다. **영향받는 판정을 실제로 선별하는 절차와 그것을 가능하게 하는 원장 레코드 구조는 §3.3.3에 정리한다.** 핵심은 판정 레코드에 "이 판정이 참조한 근거 필드" 목록이 남아 있어야 역방향 조회가 성립한다는 점이다.

변경 유형에 따른 처리 방식은 다음과 같다.

| 변경 유형 | 처리 |
|---|---|
| 메타데이터 수정·중복 제거 등 비본질적 변경 | `NO_ACTION` |
| 점수 또는 집계 값의 경미한 변경 | `RERANK_ONLY` |
| 기존 명제를 지지하거나 반박하는 새 근거 | `REOPEN_L3` |
| 새로운 분석이 필요한 원천 데이터 추가 | `REOPEN_L2` |
| 스키마·온톨로지·집계 규칙 변경 | `FULL_REBUILD` |

재검토 루프는 정기 데이터 갱신과 중대 사건 기반 갱신을 모두 지원한다.

* 정기 갱신: 월별 또는 분기별 데이터 릴리스 반영
* 사건 기반 갱신: 임상 효능 결과, 개발 중단, 안전성 경고, 새로운 GWAS·QTL 공개 등

기존 판정은 수정하거나 삭제하지 않고 원장에 유지한다. 새로운 판정은 이전 판정을 대체하는 별도 버전으로 기록한다.

```text
Decision v1: 기각
        ↓ 새로운 근거
Decision v2: 보류
        ↓ 추가 임상 근거
Decision v3: 조건부 채택
```

이 버전 체인은 두 가지를 동시에 보장한다. 첫째, 과거 판정이 당시 근거에 비추어 타당했는지를 사후에도 검증할 수 있다. 둘째, **"기각 → 부활" 궤적 자체가 §4.2 재검토 복구율의 원자료가 된다.**

#### 3.2.4 순위 산출 엔진 — 루프 바깥의 결정론적 계산부

세 루프가 근거를 모으고 명제 상태를 확정하면, **순위 자체는 루프 안이 아니라 별도의 결정론적 계산부에서 산출한다.**

**LLM은 순위를 매기지 않는다.** 이는 성능 판단이 아니라 §4.3 S6에서 연역된 제약이다. 같은 스냅샷에 같은 근거 값이 나와야 차분 엔진의 Δ 계산이 성립하는데, LLM이 후보 간 우열을 직접 판정하면 실행마다 순위가 흔들려 S6이 무너지고 메모리 계층 전체가 성립하지 않는다.

| 구분 | 담당 | 성격 |
|---|---|---|
| 근거 수집·정규화 | L2 Explorer (LLM) | 자율 |
| 명제 상태 제안 (`SUPPORTED`~`UNKNOWN`) | L3 Analyst·Critic (LLM) | 자율 |
| **점수 계산 및 정렬** | **Ranker** | **결정론적·버전 고정** |

**입력과 규칙.** Ranker는 벌크 기저 값, cis-MR 결과, 신규성 메타, 그리고 L3가 확정한 명제 상태를 입력받아 버전이 고정된 규칙으로 점수를 계산한다. 규칙 버전은 근거 스냅샷 버전과 함께 원장에 기록되므로, "이 순위가 어떤 규칙과 어떤 데이터에서 나왔는가"를 사후에 재구성할 수 있다.

**명제 상태의 반영 원칙**은 다음과 같이 구분한다. 근거 부재와 반증은 성격이 다르므로 같은 방식으로 처리하지 않는다.

| 상태 | 반영 방식 |
|---|---|
| `SUPPORTED` / `PARTIAL` | 근거 강도에 따라 가산 |
| `UNKNOWN` | **감점이 아니라 불확실성 폭 확대.** 0으로 대치하지 않는다(§4.3 S5) |
| `CONFLICTED` | 불확실성 확대 + 상충 플래그 노출 |
| `REFUTED` | 해당 명제가 핵심 명제면 순위 산출에서 제외하고 기각 권고로 분기 |

**출력 규격.** 단일 종합 점수만 내보내지 않는다. 성분별 점수, 적용 가중치, 결측 처리 내역, 불확실성 폭을 함께 노출한다. 신규성과 근거 강도의 교환 관계도 Ranker 안에서 명시적 가중치로 처리하며 그 값을 드러낸다. §4.3 S8(기전 특이성 점검)이 성립하려면 이 성분 병기가 전제되어야 한다.

> **Critic의 판정이 순위에 반영되는 경로도 결정론적이다.** Critic이 명제 상태를 바꾸면 Ranker가 같은 규칙으로 다시 계산할 뿐, Critic이 점수를 직접 조정하지 않는다. 이 분리가 없으면 "왜 이 후보의 순위가 내려갔는가"를 추적할 수 없다.

#### 3.2.5 루프 외부의 품질 관문

세 개의 핵심 루프 외에 별도의 반복 루프를 추가하지 않고, 카드 산출과 최종 판정 사이에 두 개의 품질 관문을 둔다.

##### Evidence Audit Gate

가설 카드의 각 주장과 출처가 실제로 일치하는지 검사한다.

주요 검사 항목은 다음과 같다.

* 인용 문헌이 해당 주장을 직접 지지하는가
* 질환·표적·개입 방향이 일치하는가
* 약물과 직접 표적이 정확히 연결되었는가
* 다른 질환이나 동물모델의 근거가 RA 인간 근거로 과대 해석되지 않았는가
* 반증 근거가 누락되지 않았는가

검사를 통과하지 못한 카드는 Analyst 또는 Explorer로 반환한다. **반환은 카드당 횟수를 제한하며, 제한을 초과한 카드는 미통과 사유를 붙여 그대로 사람 검토로 넘긴다** — 관문이 무한 루프로 변질되지 않게 하기 위함이다.

**담당 주체는 규칙 검사와 LLM 검사의 이원 구성이다.** 출처 식별자 존재 여부, 질환·표적·방향 필드 일치, 반증 필드 비어 있음 여부는 규칙으로 결정론적 검사가 가능하다. 반면 "인용 문헌이 해당 주장을 직접 지지하는가", "동물모델 근거를 인간 근거로 과대 해석하지 않았는가"는 의미 판단이므로 별도 LLM이 담당한다. **따라서 이 관문 전체를 결정론적이라 표현하지 않으며, LLM 검사 부분은 표본 수작업 검토로 감사 정확성 자체를 검증**한다. 이 수작업 검증 결과가 §1.3 "인용 근거 정확성"의 실측치가 된다.

이 관문의 통과율이 §1.3 "인용 근거 정확성"의 산출 근거이며, §4.3 S7(명제·반증 완전성)이 검사하는 대상과 동일하다.

##### Human Review Gate

에이전트의 권고 판정과 근거 카드를 연구자가 검토한다.

연구자는 다음 중 하나를 결정한다.

* 채택
* 조건부 채택
* 보류
* 기각

에이전트 권고와 사람 판정은 별도 필드로 저장하여, 에이전트와 전문가의 판단 차이를 추적하고 이후 평가에 활용한다. 두 값이 §3.2.2와 동일한 4단계 어휘를 공유하므로, **일치율을 곧바로 §1.3 "전문가 동의율"로 계산할 수 있다.** 다만 평정 인원·척도·평가자간 신뢰도 지표를 어떻게 둘 것인지는 미정이며, 설계 방향은 §4.4에 별도로 정리한다.

#### 3.2.6 루프 설계 원칙

세 루프는 다음 원칙을 따른다.

1. **역할 분리**
   탐색, 가설 정련, 최종 사람 판정을 분리한다.

2. **근거 공백 중심 탐색**
   이미 근거가 많은 축을 반복 조사하지 않고 판정에 중요한 공백을 우선한다.

3. **반증 우선성**
   지지 근거뿐 아니라 가설을 약화시키거나 제한하는 근거를 능동적으로 수집한다.

4. **명제 단위 추적**
   후보 전체가 아니라 가설을 구성하는 개별 명제와 근거의 연결을 기록한다. 이 연결이 §3.2.3에서 `REOPEN_L3`와 `REOPEN_L2`를 구분하는 근거가 된다.

5. **제한된 자율성**
   에이전트는 정해진 상태와 분기 안에서 탐색과 정련을 수행하며, 종료 사유와 상태 전이를 기록한다.

6. **부분 재실행**
   새로운 근거가 추가되었을 때 전체 시스템을 항상 다시 실행하지 않고, 영향받는 명제와 후보만 재검토한다.

7. **사람의 최종 결정**
   에이전트는 채택·보류·기각을 권고하지만 최종 판정은 연구자가 수행한다.


### 3.3 메모리 아키텍처

원장·차분 엔진으로 구성된 메모리 계층은 LLM 에이전트 memory 분야의 기존 분류 체계와 신약개발 특화 선행 연구를 참고해 설계했다. 상세 문헌 조사는 `memory_architecture.md`에 별도로 정리했으며, 본 절은 (1) 무엇을 저장하고 어떻게 되돌리는지, (2) 그 구조를 택한 근거, (3) 기대 효과와 그 검증 방법을 정리한다.

#### 3.3.1 설계 제1원칙 — 추적 불가능한 기억은 쓰지 않는다

Seal et al.(2026, arXiv:2510.27130)이 정리한 신약개발 에이전트의 memory 구조는 short-term과 long-term으로 나뉘고, long-term은 다시 **internal**(continued pretraining·fine-tuning·model merging으로 모델 가중치에 지식을 인코딩)과 **external**(RAG·DB 등 외부 영속 저장소)로 갈린다.

본 시스템은 external long-term memory만 채택한다. 가중치에 인코딩된 지식은 "어느 시점의 어떤 근거에서 왔는가"를 되물을 수 없다. 이 배제는 성능 판단이 아니라 프로젝트 제1원칙에서 연역된 결론이며, 메모리 계층 전체의 형태를 규정한다 — 기억은 반드시 읽을 수 있고, 시점이 찍혀 있고, 되돌릴 수 있는 레코드여야 한다.

#### 3.3.2 계층별 대응 — 인지과학 분류에 얹어보면

일반 LLM 에이전트 문헌이 차용하는 Working/Episodic/Semantic/Procedural 분류(`memory_architecture.md` §2.2)에 본 시스템 구성요소를 대응시키면 다음과 같다.

| 분류 | 본 시스템 대응 | 저장 형태 | 성격 |
|---|---|---|---|
| Working | L2 Explorer의 실행 내 컨텍스트 | context window | 휘발 |
| Episodic | **탐색 이력** — 후보별 판단·호출·결과 | 단계별 레코드 | 영속 |
| Semantic | OT 벌크 기저 · 지식그래프 · 문헌 | 스냅샷 + 그래프 | 영속·버전 고정 |
| Procedural | 도구 호출 규약 · 심사 규칙 | 코드 | 정적 |
| — | **원장** — 사람의 판정 | append-only 레코드 | 영속·불변 |

주목할 점은 **원장이 기존 taxonomy 어디에도 정확히 대응하지 않는다**는 것이다. 일반 memory 문헌의 분류는 에이전트 자신의 경험·지식·절차를 다루지만, 원장이 담는 것은 *사람 전문가의 판정*이다. Seal et al.이 언급한 공유 조직 메모리(shared organisational memory)가 가장 가까우나 그 역시 에이전트 간 공유를 전제한다. 이 항목이 taxonomy 밖에 있다는 사실 자체가 본 시스템이 "자율 에이전트"가 아니라 §1이 규정한 **"사람의 대체가 아닌 보조 도구"**임을 구조적으로 드러낸다.

#### 3.3.3 동작 방식 — 원장과 차분 엔진

원장은 기록의 역할, 차분 엔진은 그 위에서 도는 질의·트리거다. 원장은 append-only 불변 저장소로서 그 자체가 감사 대상이므로 어떤 로직도 담지 않는다. 반대로 차분 엔진은 규칙이 개정될 수 있는 연산부다. 둘을 합치면 "판정 기록"과 "판정 해석"이 뒤섞여, 로직이 바뀔 때 과거 기록의 의미까지 소급 변동하는 문제가 생긴다.

**원장 레코드 구성.** 판정 한 건은 최소한 다음을 담는다.

| 필드 | 내용 |
|---|---|
| 후보·가설 식별자 | HGNC 기준 유전자 및 해당 가설 |
| 판정 | 채택 / 조건부 채택 / 보류 / 기각 |
| 사유 코드 | 판정 이유를 통제 어휘로 (예: `MR_방향_불명`, `성약성_부족`, `안전성_우려`) |
| **의존 근거 필드** | 이 판정이 실제로 참조한 근거 항목 목록 |
| 근거 스냅샷 버전 | 각 소스의 릴리스 식별자 (OT 24.03, GTEx v8 등) |
| 이전 판정 식별자 | 재판정인 경우 직전 버전 (§3.2.3 버전 체인) |
| 판정 변경 유발 근거 | 재판정을 촉발한 Δ 항목 |
| 에이전트 권고 / 사람 판정 | 두 값을 별도 필드로 분리 저장 (§3.2.5) |
| 판정자·시각 | 감사 추적용 |

의존 근거 필드가 차분 엔진의 작동 근거다. 사유 코드만으로는 "무엇이 바뀌면 이 판정이 흔들리는가"를 알 수 없다. 판정 시점에 어떤 필드를 참조했는지 명시적으로 남겨야 역방향 조회가 성립한다.

**차분 엔진의 재검토 판정 절차.**

```
L1이 새 스냅샷 수집 → 이전 버전과 필드 단위 비교
        ↓
변경된 근거 필드 집합 Δ 산출
        ↓
원장 역방향 조회: 의존 근거 필드가 Δ와 교집합을 갖는 판정만 선별
        ↓
변경 방향이 판정을 뒤집을 수 있는가 판단
   (예: `MR_방향_불명`으로 기각 + 해당 후보의 cis-MR 값이 Δ에 포함 → 해당)
        ↓
§3.2.3의 변경 유형 분류 적용 → 재실행 수준 결정
        ↓
재검토 큐 → L2 또는 L3 재진입 (기존 탐색 이력 재사용, 백지 재시작 아님)
        ↓
Arbiter 재판정 → 원장에 새 레코드 append (이전 레코드는 불변 유지)
```

핵심은 전수 재실행이 아니라 선별 재실행이라는 점이다. 후보 풀이 수백 개라도 특정 근거 갱신이 건드리는 판정은 대개 소수이므로, 재검토 비용이 근거 갱신 규모에 비례하고 후보 수에는 비례하지 않는다.

#### 3.3.4 결정론이 성립하는 범위

위 절차 중 사람의 재판정을 제외한 전 과정이 결정론적이다. 같은 스냅샷 쌍을 입력하면 같은 재검토 큐가 나온다. 이것이 S6("같은 스냅샷 N회 실행 시 근거 값 일치율 100%")이 메모리 계층의 전제 조건인 이유다 — 근거 값이 실행마다 흔들리면 Δ 자체가 신뢰할 수 없어 차분 엔진이 성립하지 않는다. 다만 S6이 요구하는 것은 **최종 근거 값의 재현성이지 L2 탐색 경로의 재현성이 아니다.** 경로·깊이·반증 범위는 §3.2.1의 규정대로 에이전트 자율에 맡긴다.

**Generative Agents·MemGPT 계열과 다른 이유는 성능이 아니라 문제 종류다.** 저쪽이 푸는 문제는 컨텍스트 한계를 넘는 대화·관찰 스트림의 압축과 선별이며, 따라서 무엇을 잊을지 판단하는 휴리스틱이 핵심이 된다. 본 시스템이 푸는 문제는 유한한 후보 집합에 대한 사람 판정의 감사 가능한 축적이므로, 망각 자체가 요건이 아니고 오히려 금지된다(append-only). 같은 "memory"라는 이름을 쓰되 요구사항이 반대에 가깝다.

#### 3.3.5 기대 효과와 검증

메모리 계층이 노리는 효과는 두 가지다.

**첫째, 판정의 시효 관리.** 근거는 계속 갱신되는데 판정은 한 시점에 고정된다. 메모리 계층 없이는 "3개월 전 기각한 후보가 지금도 기각 대상인가"를 물을 방법이 전량 재실행뿐이다. 차분 엔진은 이를 선별 재실행으로 바꾼다.

**둘째, 탐색 재개.** 탐색 이력이 있으면 재검토가 백지에서 시작하지 않는다. 이전 회차에 이미 호출한 근거를 다시 호출하지 않으므로 재검토 비용이 초기 탐색보다 낮다.

검증은 §4.2 재검토 복구율에서 한다. 주 지표는 **영향 판정 재현율·정밀도와 전체 재실행 대비 호출 절감**이며, 실제로 뒤집힌 판정이 임상에 진입한 사례는 정성적 사례 연구로 병기한다.

> ⚠️ **복구 사례가 0건일 수 있다.** 관찰 기간이 짧으면 판정이 뒤집힌 사례 자체가 없을 수 있다(§4.1 표본 수 위험과 같은 뿌리다). 그러나 정량 지표를 사례 존재에 걸어두지 않았으므로 평가는 성립한다 — 영향 판정 재현율·정밀도는 근거가 변경된 후보만 있으면 계산되고, 호출 절감은 양성 표적 존재 여부와 무관하다.


### 3.4 데이터

#### 후보 풀 구성

| 단계 | 처리 | 규모(추정) |
|---|---|---|
| 모집단 | HGNC 단백질 부호화 유전자 전체 | 약 20,000 |
| 1차 열거 (Enumerator) | RA 연관 검색 · 문헌 마이닝 · 지식그래프 이웃 · LLM 발산 확장 | 수천 |
| 사전 심사 (Prescreener) | `DROP_SCOPE` 판정 — **범위 밖 후보만** 제외 | — |
| **순위 대상 풀** | 순위를 부여하는 후보 집합 | **수백 규모** |

> **Recall의 분모는 풀 크기가 아니라 양성 표적 수다.** 풀 크기는 무작위 베이스라인의 기대값, 순위 난이도, 정규화 순위에 영향을 주지만 Recall 계산의 분모가 아니다. 이 구분을 §4.1의 지표 정의와 일치시킨다.

**`DROP_SCOPE`와 `HOLD_DATA`의 분기.** 두 상태를 혼동하면 신규성 목표가 무너진다.

| 상태 | 조건 | 처리 |
|---|---|---|
| `DROP_SCOPE` | 비단백질 부호화 유전자 · 현재 범위 밖 개입 형태 · 식별자 오류가 해소되지 않음 | 풀에서 제외. 스코프 정의(§1.4)에 근거하므로 근거 갱신과 무관 |
| `HOLD_DATA` | 분석할 공개 근거가 부족해 현재 판정 불가 | **풀에 유지.** 순위에서 별도 표시하되 모집단과 제외 기록에서 제거하지 않으며, 근거 갱신 시 재진입 |

> **데이터 부재를 제외 사유로 쓰지 않는다.** 근거가 없다는 사실은 "가치 없는 후보", "연구되지 않은 신규 후보", "현재 DB 커버리지 밖", "식별자·동의어 매핑 실패" 중 무엇인지 구분해주지 않는다. 신규성을 목표로 하는 시스템이 미연구 후보를 제거하면 **알려진 표적 쪽으로 선택 편향이 발생**해 §1.3의 신규성 목표와 정면으로 충돌한다.

**LLM 발산 확장의 재현성 통제.** 열거 단계에 LLM 발산 확장이 포함되므로 실행마다 풀 구성이 달라진다. 평가 실행에서는 다음 중 하나를 적용하고 그 방식을 결과와 함께 보고한다.

1. temperature 0 + 고정 프롬프트로 단일 실행
2. 복수 시드 실행 결과의 합집합을 풀로 고정
3. 3~5회 반복 실행의 **열거 재현율 평균과 편차**를 보고 (§4.1 E0)

단일 실행 결과만 쓰면 우연히 유리하게 나온 풀을 선택할 여지가 남으므로, 3번을 기본으로 하고 1번을 재현용 고정 실행으로 병기한다.

> ⚠️ **LLM 사전 지식은 누출 경로다.** 데이터 소스를 시점 고정해도, 발산 확장에 쓰이는 LLM의 학습 데이터에는 컷오프 이후 임상 진입 정보가 포함되어 있을 수 있다. 대응은 §4.1 누출 차단에서 다룬다.

### 3.7 제약 및 후속 확장

- 본 에이전트는 근거 기반 가설 및 후보 제안까지만 수행하며, wet-lab 검증은 인간 연구자에게 위임한다.

**내재적 한계**
1. **입력 규격 고정** — OT 16인자·LOEUF·cis-MR은 단백질 부호화 유전자를 전제한다.
2. **도메인 데이터 의존성** — cis-MR은 GWAS·QTL이 축적된 질환에서만 구동된다. RA는 충족되나 이식 시 무효화될 수 있다.
3. **탐색 폭 축소** — 도구 집합이 좁아 예외적 질의 대응력이 낮다. 비교 가능성을 얻는 대신 폭을 잃는 교환이다.
4. **커버리지 비결정성** — 후보별 탐색 깊이가 다르므로 심화 근거가 균일하지 않다. 벌크 기저는 전수 확보되나 MR·문헌 심층은 후보마다 다르다. 이 편차는 §3.2.1의 종료 사유 기록으로 노출한다.
5. **RA 전용 구현** — 데이터 배선·벤치마크가 RA 고유다. 이식 시 재사용되는 것은 파이프라인 형태와 코드 골격뿐이다.


## 4. 평가 방식

근거를 시점으로 잘라 과거 시점에서 선택한 타겟 가설이 미래에 임상 시험으로 이어진 비율/후속 성공의 비율로 채점한다.

평가는 두 축이다. **E1이 "작동하는가", E2가 "각 부품이 제 값을 하는가"**를 답한다.

### 4.1 E1 — 시간 분할 예측 (주 평가)

#### 설계

```
근거를 컷오프 T 이전으로 제한
        ↓
시스템 실행 → 순위 산출
        ↓
T 이후 RA 임상에 진입한 표적을 얼마나 상위에 두었는가
```

해당 테스트는 T를 여러 시점으로 설정하여 진행하며, 특정 논문이 발행되기 이전의 시간으로 결정한다. 또한, 미래 시점의 데이터 누출이 일어나 생기는 오차를 신경써야 한다.

다만, 제안한 표적 가설이 실제 임상에 들어갔다고 해서 유효한 가설이 되는 것은 아니다.
따라서 해당 가설의 검증을 세 단계로 나누어 진행한다.

| 단계 | 양성 정의 |
|---|---|
| **E1a — 신규 임상 진입 예측** | T 이후 관찰기간 내 RA 임상시험에 최초 진입한 표적–적응증 쌍 |
| **E1b — 임상 PoC 예측** | E1a 표적 중 사전 지정된 Phase II 이상 1차 효능 평가변수를 충족한 표적–적응증 쌍 |
| **E1c — 후속 개발 예측** | PoC 이후 후속 시험 개시·상위 단계 진입·승인 등이 확인된 표적–적응증 쌍 |

#### 단계별 지표 분리 — 생성 실패와 순위 실패를 구분한다

**후보를 애초에 열거하지 못한 것과 열거했으나 낮은 순위를 준 것은 다른 실패다.** 하나의 End-to-end Recall로 합치면 두 오류가 섞여 Enumerator·Prescreener·Ranker 어느 쪽을 고쳐야 하는지 알 수 없고, §4.2에서 LLM 발산 확장과 사전 심사의 가치를 절제 실험으로 측정할 수도 없다. 따라서 네 지표로 분리한다.

| 단계 | 지표 | 답하는 질문 |
|---|---|---|
| **E0 — 후보 생성** | 열거 재현율 (Nomination recall) | 미래 양성 표적을 후보 풀에 포함시켰는가 |
| **E0′ — 사전 심사** | 양성 생존율 (Positive survival rate) | 양성 후보를 심사에서 잘못 제거하지 않았는가 |
| **E1 — 순위화** | 조건부 Recall@50 | **풀에 들어온** 양성을 상위에 올렸는가 |
| **전체** | End-to-end Recall@50 | 생성부터 순위까지 최종적으로 회수했는가 |

- **Recall의 분모는 양성 표적 수다.** 조건부 Recall의 분모는 풀에 포함된 양성 수, End-to-end Recall의 분모는 전체 양성 수다. 후보 풀 크기는 무작위 베이스라인과 정규화 순위에만 관여한다.
- E0가 낮으면 Ranker를 아무리 개선해도 End-to-end가 오르지 않는다. **E0를 먼저 보고한 뒤 조건부 Recall을 제시**한다.
- 양성 생존율이 1 미만이면 사전 심사가 양성을 제거했다는 뜻이므로, `DROP_SCOPE` 규칙(§3.4)을 재검토한다. 데이터 부재를 `HOLD_DATA`로 유지하는 설계가 이 지표를 방어한다.

#### 평가 단위 — 시스템 출력 단위와 정답 단위를 맞춘다

시스템의 가설 단위는 **유전자 × 개입 방향 × 조직·세포·환자 맥락**인데, 임상 진입 기록에서 얻는 정답은 대체로 **유전자 × 적응증**이다. 이 불일치를 방치하면 억제해야 할 표적을 활성화하자고 예측해도 정답 처리되고, 전체 RA에서는 실패했으나 특정 하위군에서만 효과가 있었던 경우도 적중으로 계산된다.

| 평가 | 채점 단위 | 성격 |
|---|---|---|
| **E1a-Target** | 표적 – RA 최초 임상 진입 | 주 지표 |
| **E1a-Direction** | 표적 + 개입 방향(`dir`) 일치 여부 | 보조 |
| **E1b-Program** | 표적 + 방향 + 약물양식 수준의 임상 PoC | 보조 |
| **맥락 평가** | 예측한 조직·세포·환자군이 실제 시험 맥락과 일치하는지 | 정성 |

- ChEMBL의 작용 유형 주석 등으로 방향이 확정되지 않는 프로그램은 `direction-unresolved`로 분류하고 방향 채점에서 제외하되, 그 건수를 함께 보고한다.
- **표적 수준 지표를 주 지표로 유지하되, 그것을 "시스템 가설의 정확도"로 표현하지 않는다.** 시스템은 방향과 맥락까지 주장하므로, 표적만 맞힌 것은 부분 적중이다.
- 방향·맥락 수준으로 내려갈수록 양성 수가 줄어 아래 표본 수 위험이 심해진다. 따라서 이들은 주 지표가 아니라 보조로 두고 표본 제약을 명시한다.

#### 정답 집합 구성

| 구분 | 정의 |
|---|---|
| 양성 | T 이후 RA 임상시험이 최초 개시된 표적 |
| 배경 | 관찰기간 내 임상 진입이 확인되지 않은 표적. 생물학적 음성을 의미하지 않는다 |
| 제외 | T 이전에 이미 RA 승인, 임상 진행 중이던 표적 |
| 검열 | 관찰기간이 완료되지 않은 최근 컷오프는 별도로 표시한다 |

> **다중표적 모달리티 처리 규칙.** 최근 RA 파이프라인에는 T세포 인게이저 등 다중 표적을 동시에 겨냥하는 후보가 포함된다. §1.4가 다중 표적 조합을 스코프에서 제외하므로, ChEMBL 표적 매핑 결과가 복수인 약물은 **단일 주표적이 명확히 식별되는 경우에만 해당 표적으로 계수하고, 그렇지 않으면 정답 집합에서 제외**한다. 제외 건수는 별도로 기록해 표본 축소 폭을 드러낸다.

#### 누출 차단

다른 소스로부터 정보가 누수되는 것을 방지하기 위해 모든 소스의 시간을 T로 구성해야 한다.

| 소스 | 차단 방법 | 제약 |
|---|---|---|
| OT Association Evidence | T 이전 분기 릴리스 사용 | 분기 릴리스 아카이브 이용 가능 |
| **OT Target Prioritisation (16인자)** | 동일 | **현재 형태의 뷰는 Platform 23.12 공개 — T가 그 이전이면 사용 불가** |
| 문헌 검색 | 발행일 필터 | 가능 |
| AACT | 등록·개시일 필터 | 가능 |
| GWAS 요약통계 | 발표일 기준 선정 | 가능 |
| eQTL | T 이전 릴리스 | GTEx v7/v8은 가능. eQTLGen(2021.09)은 T≥2022에서 가능 |
| pQTL | T 이전 공개 자원 사용 | INTERVAL 등은 2018년부터. UKB-PPP 주요 결과는 2023.10 공개 |
| **LLM 사전 지식** | 아래 별도 항목 | **완전 차단 불가 — 상한 추정으로 대응** |

**주 컷오프는 T = 2023-12-31로 고정한다.** 월 단위가 아니라 릴리스 기준 날짜로 못박는 이유는 두 자원의 공개 시점이 2023년 4분기에 몰려 있기 때문이다. UKB-PPP 주요 pQTL 결과가 2023년 10월, OT Target Prioritisation 16인자가 Platform 23.12에 공개되었으므로, **둘을 모두 쓰려면 2023년 12월 이후여야 한다.** "2023년 하반기"라는 표현은 이 경계를 넘나들어 부적절하다.

| 안 | 컷오프 | 사용 근거 | 대가 |
|---|---|---|---|
| **A (기본)** | 2023-12-31 | OT 23.12 전체 + UKB-PPP | 관찰 기간 약 2년 8개월로 축소 |
| B | 2023-09/10 | OT Association + 기존 pQTL만 | 16인자 전체 포기 — 벌크 기저의 성약성·안전성 축 상실 |
| **C (예비)** | 자유 | 16인자를 **원천 소스에서 직접 재구성** (LOEUF·DepMap·COSMIC·ChEMBL 성약성·MGI 등) | 구현 공수. 대신 릴리스 날짜 의존성이 사라져 컷오프를 앞당길 수 있음 |

> C안은 §3.4의 입장("원천 값은 신뢰하되 OT의 집계 방식은 예측력이 검증되지 않았다")과 오히려 정합적이다. **A안을 기본으로 하되, 구현 0단계에서 양성 표적이 부족한 것으로 확인되면 C안으로 전환해 관찰 기간을 되산다.**

**LLM 사전 지식 누출.** 데이터 소스를 모두 시점 고정해도, 후보 열거에 쓰이는 LLM의 학습 데이터에는 T 이후 임상 진입 정보가 포함되어 있을 수 있다. 이는 데이터 배선으로 차단할 수 없는 경로이며, 방치하면 E0 열거 재현율이 시스템의 능력인지 모델의 기억인지 구분되지 않는다. 대응은 다음과 같다.

1. **발산 확장을 폐쇄형으로 쓰지 않는다** — 모델의 내부 지식만으로 후보를 생성하게 하지 않고, T 이전 문맥(문헌 스니펫·지식그래프 이웃)을 제공한 상태에서의 확장으로 제한한다.
2. **LLM 발산 확장 포함/제외 두 조건의 E0를 병기**한다. 두 값의 차이가 누출 상한의 추정치가 된다.
3. 완전 차단이 불가능함을 결과에 명시한다.

> 이 문제는 §4.2 절제 실험의 "LLM 심사·발산 확장 제거" 항목과 같은 실행에서 함께 측정되므로 추가 비용이 크지 않다.

#### 지표

| 지표 | 정의 |
|---|---|
| **Recall@50** | 상위 50개 안에 든 양성 표적 |
| Recall@100 | 보조 |
| 평균 순위 | 양성 표적들의 평균 순위 |
| 정규화 순위 | 후보 풀 크기로 정규화한 값 (풀 크기 변동 대비) |

#### 베이스라인 — 평가를 의미 있게 만드는 부분

| 베이스라인 | 답하는 질문 |
|---|---|
| 무작위 | 최소 기준 |
| **OT 연관 점수 단독 정렬** | **"그냥 Open Targets 쓰면 되지 않나"** |
| **최근성·빈도 정렬 단독** | **"OriGene 방식과 뭐가 다른가"** |
| 문헌 빈도 단독 | 인기 편향 대비 |

**2번과 3번이 심사에서 반드시 나올 질문에 수치로 답한다.**

#### 표본 수 위험 — Phase 0에서 최우선 확인

T=2023 기준 관찰 기간은 3년 내외로, **신규 진입 표적이 10개 미만이면 Recall이 불안정**해진다. 예비 조사에서 이 기간 RA에 새로 등장한 신규 기전 후보는 소수로 확인되므로, 위험이 실재한다고 보고 대응을 준비한다.

1. 컷오프를 앞당김 (예: T=T-N) — 양성 증가, 단 MR 데이터 더 부족
2. **면역매개 염증질환(IMID) 전반으로 확장** — RA·PsA·AS·IBD·건선·SLE. 기전을 공유하므로 표본이 크게 늘어남
3. 표적-적응증 쌍 단위로 계수

**주 평가는 RA로 하되, Phase 0에서 양성 표적이 10개 미만으로 확인되면 IMID 확장본을 강건성 검사가 아니라 공동 주 평가로 승격한다.** 실제 개수 확정은 AACT + ChEMBL 표적 매핑으로 직접 계수해 판단한다.


### 4.2 E2 — 절제 연구 (설계 정당화)

각 구성 요소가 성능에 미치는 영향을 분석하기 위해 각 구성요소를 하나씩 제거하여 평가한다.

#### E2a — 순위에 영향을 주는 절제

E1과 동일한 설정에서 구성요소를 하나씩 제거하고 지표 변화를 측정한다. **제거 대상이 속한 단계에 따라 보는 지표가 다르다** — Enumerator·Prescreener 계열은 E0 열거 재현율과 양성 생존율로, Ranker에 입력되는 근거 계열은 조건부 Recall@50으로 본다(§4.1).

| 제거 대상 | 대응 설계 결정 |
|---|---|
| **ReAct 탐색 루프** | 깊이 우선 채택 |
| **cis-MR** | 인과 및 방향 추가 |
| **벌크 기저** | 백지 시작 방지 |
| **LLM 심사** | 노이즈 제거 |
| **Critic** | 반증 수집 및 통합 |
| **신규성 신호** | OriGene 방식 채용 |
| **LLM 발산 확장** | 후보 열거 폭 확대 — E0 열거 재현율로 측정 |

#### 재검토 복구율 — 메모리층 전용 지표

현재 시스템은 데이터를 저장하는 메모리 아키텍처를 가지고 있으며 실제 신약 개발 타겟 발굴에 도움이 되는지 파악을 위한 테스트이다. 이를 위해 E1의 시간 분할 장치를 재사용한다.

```
T 스냅샷으로 판정  →  T+3년 근거 주입  →  차분 엔진 발동
      ↓
뒤집힌 판정 중 실제로 임상에 진입한 표적이 있는가
```

**정량 지표는 다음 네 가지다.** 모두 근거가 변경된 후보만 있으면 계산되며, 판정이 실제로 뒤집혔는지나 그 표적이 임상에 진입했는지와 무관하게 측정된다.

| 지표 | 정의 |
|---|---|
| 변경 후보 수 | 실제로 근거가 변경된 후보의 수 (모수) |
| 재검토 대상 수 | 시스템이 큐에 올린 후보의 수 |
| **영향 판정 재현율** | 재검토가 필요했던 판정 중 시스템이 포착한 비율 |
| **영향 판정 정밀도** | 시스템이 올린 판정 중 실제로 변경이 필요했던 비율 |

여기에 **전체 재실행 대비 호출 절감**(선별 재실행 시 호출 수 ÷ 전수 재실행 시 예상 호출 수)을 더해 §3.3.5의 두 번째 효과를 측정한다.

**정성 지표 — 판정 복구 사례.** "T 시점에 기각했으나 이후 근거로 되살아났고 실제로 개발이 진행됐다"는 사례는 **사례 연구로 제시한다.** 한 건의 재현은 시스템이 작동할 수 있다는 존재 증명이지 유용성의 정량적 증명이 아니므로, 메모리층의 가치를 이 사례에 걸지 않는다. 관찰 기간이 짧아 사례가 0건이어도 위 정량 지표는 그대로 성립한다.

### 4.3 보조 — 도구 정확성과 점검

| # | 항목 | 기준 |
|---|---|---|
| S1 | **OT 값 정합성** | OT 원본과 불일치 0 |
| S2a | 기지 단일표적 회수 | TNF, IL6R, MS4A1, IL1R1이 후보 풀에 포함되고 상위권에 위치 |
| S2b | 복합 기전 매핑 정확성 | abatacept → CD80/CD86–CD28 공동자극 차단, JAK 억제제 → 약물별 JAK target set으로 정확히 표현 |
| S3 | **IL6R MR 방향** | 분석 방법과 도구변수 수에 따라 적용 가능한 진단 지표를 선택 |
| S4 | 음성 대조 | RA 무관 유전자 10개가 하위 50% |
| S5 | 결측 처리 | NA가 0으로 대치되지 않음 |
| S6 | **근거 값 재현성** | 같은 스냅샷 N회 실행 시 **일치율 100%** (탐색 경로가 아닌 최종 근거 값 기준 — §3.3.4) |
| S7 | 명제·반증 완전성 | 상위 50개에 세 주장 + 출처 100%, 반증 필드 비어 있지 않음 (Evidence Audit Gate 통과 기준과 동일 — §3.2.4) |

> **S1·S2가 관문이다.** 통과 전에는 E1으로 넘어가지 않는다. S1 실패는 조회·버전 오류, S2 후보 누락은 열거·조인 문제를 우선 의심하고, 후보는 존재하지만 순위가 낮으면 점수·근거 집계 및 표적 매핑을 점검한다.

TNF-α·IL-6R·CD20·JAK 등 검증된 분자 표적과 승인 치료제가 다수 존재하며, IL-17A 등 다른 IMID에서 성공했지만 RA에서는 임상적 유효성이 확립되지 않은 기전도 존재한다. 후자는 S2의 정답 집합에 넣지 않고 **S8 기전 특이성 점검**에 사용한다.

| # | 항목 | 기대 출력 |
|---|---|---|
| S8 | **기전 특이성 — IL-17A** | 아래 네 조건을 동시에 만족 |

1. **생물학적 연관 축은 높게 나온다** — RA 염증 경로·발현 문헌이 실재하므로 낮게 나오는 것이 오히려 비정상이다
2. **임상 번역 근거 축은 부정적 또는 제한적으로 표시된다** — RA 임상에서 유효성이 확립되지 않은 이력이 반영되어야 한다
3. **다른 IMID 성공 근거가 RA 근거로 전이되지 않는다** — Critic 검사 항목 중 "다른 질환의 근거를 RA에 과도하게 전이하지 않았는가"의 실증 사례에 해당한다
4. **최종 우선순위는 낮거나 조건부로 산출된다** — 단, 1~3의 성분이 병기된 상태여야 한다

> **이 점검은 성분 점수를 병기하는 설계이기 때문에 성립한다.** 종합 점수 하나만 내는 시스템에서는 "생물학적 연관은 높으나 임상 번역 근거가 부정적"이라는 상태를 표현할 방법이 없다. 낮은 종합 순위만 확인하는 방식은 시스템이 옳게 판단했는지 우연히 낮게 나왔는지를 구분하지 못하므로 채택하지 않는다.
>
> S8은 사실상 **Critic 전용 점검**이다. Critic을 제거한 조건에서 조건 2·3이 무너지는지를 함께 확인하면 §4.2 절제 연구의 정성적 근거가 된다.

### 4.4 전문가 동의율 (검토 중)

§1.3의 세 지표 중 전문가 동의율만 측정 설계가 확정되지 않았다. 현재 도입을 검토 중이며, 방향은 다음과 같다.

**데이터 소스는 이미 확보되어 있다.** Human Review Gate(§3.2.5)가 에이전트 권고와 사람 판정을 동일한 4단계 어휘(채택 / 조건부 채택 / 보류 / 기각)로 별도 필드에 저장하므로, 두 값의 일치율이 곧 동의율이 된다. 별도 설문을 돌리지 않아도 파이프라인 운용 기록에서 산출된다.

**미정 항목은 평정 설계다.** 평정 인원, 척도(4단계 판정을 그대로 쓸지 Likert 척도를 병용할지), 평가자간 신뢰도 지표(Cohen's Kappa 또는 ICC)를 어떻게 둘 것인지가 남아 있다. 단일 평정자만 참여하면 신뢰도를 보고할 수 없으므로, 복수 전문가 확보 가능성에 따라 설계가 달라진다.

이 지표는 확정 전까지 대표 지표가 아니라 보조 점검으로 둔다.
