## 1. 목표와 목적

### 배경

신약개발은 유전체, 전사체, 단백체 등 오믹스(Omics) 데이터의 폭발적인 증가와 자연어 처리(NLP) 기술의 발전으로 인해 혁신적인 변화의 시기를 맞고 있다. 후보 물질의 in-silico 가설 생성은 연구자가 문헌을 검색, 데이터베이스 조회 및 약물성 검토를 반복적으로 수행하는 구조이다. 해당 부분을 에이전트가 담당함으로써 후보 생성과 우선순위화 병목을 줄이고, 이를 통해 후속 검증 단계에 투입되는 후보 수와 비용을 최소화하는 것이 해당 프로젝트의 배경이다.

RA/PsA 파이프라인은 75~100개 이상 기업이 경쟁할 만큼 활발하고 시장 규모도 크다(2026년 기준 RA 약 $28~39B, PsA 약 $11~14B). 그러나 새로 나오는 치료제도 대부분 이미 검증된 표적(TNF/IL-6/IL-17/IL-23/JAK/TYK2) 안에서의 변주에 그쳐, 근골격계 증상 완전 조절 같은 미충족 수요가 여전히 남아있다.

신약개발 초기 단계에서 후보 하나당 근거를 모으는 비용은 상당하다. 조직 발현·유전학·성약성·시험 이력·안전성을 모두 확인하려면 숙련자가 후보당 며칠씩 걸리므로, 실제로는 3~5개만 검토하고 300개는 못 본다. 그 결과 선택이 친숙도에 지배되고, 후보마다 조사 깊이가 달라 비교가 불가능해지며, 반박 근거는 거의 수집되지 않는다. 이를 해결하기 위해 Agent가 담당하여 후보 생성과 우선순위화 병목을 줄이고, 이를 통해 후속 검증 단계에 투입되는 후보 수와 비용을 최소화하는 것이 해당 프로젝트의 목적이다.

### 목적

문헌 검색, 오믹스데이터와 지식그래프 설계 및 구축 등 파편화된 정보들을 통합해, RA에 대한 신규 치료 표적 후보 가설을 자율적으로 생성하고 근거 기반으로 검증하는 사이클을 개발한다. 연구진에게는 **"사람의 대체가 아닌 보조 도구"**로서 작동한다.

### 목표

- 근거기반성(Evidence Groundedness): 생성되는 모든 가설과 그 검증 과정은 추적 가능한 문헌과 데이터 출처로 뒷받침되어야 한다.
- 신규성(Novelty): 기존 데이터베이스(ChEMBL, OpenTargets 등)에 해당 질환과 명시적으로 연관되지 않은 타겟과 재창출 후보를 발굴해야 한다.
- 설명가능성(Explainability/Traceability): 가설에 이르는 추론 사슬, 근거, 한계점 등이 사람 전문가가 검토할 수 있는 형태로 제시되어야 한다.

이에 대한 평가 지표는 다음과 같다:
- 인용 근거 정확성: 에이전트가 제시한 근거 문헌이 실제로 해당 주장을 지지하는지 비율
- 신규성 비율: 기존 데이터베이스 대비 새롭게 제안된 타겟·재창출 후보의 비율
- 전문가 동의율: 사람 전문가 검토에서 "타당하다"고 평가되는 가설의 비율

### 범위

| | 포함 | 제외 |
|---|---|---|
| **단계** | 표적 발굴 (in-silico 가설 생성) | 히트 발굴, 리드 최적화, 임상 설계 |
| **질환** | **RA 단독** | PsA·AS·OA·Gout (후속 확장) |
| **표적 유형** | HGNC 단백질 부호화 유전자 | ncRNA, 미생물 표적, 세포치료제 |
| **개입 형태** | 단일 표적 직접 개입 (`dir` = 억제/작용) | 다중 표적 조합 |
| **검증** | in-silico 근거 조립 | wet-lab 실험 (인간 연구자에 위임) |
| **산출** | 순위화된 가설 카드 + 판정 메모리 | 화합물, 실험 프로토콜 |


## 2. 용어
 
### RA 관련
 
- **류마티스 관절염(RA)**: 면역계가 자기 관절 조직을 공격하는 자가면역질환. TNF-α·IL-6·IL-17·JAK 등 명확한 분자 타겟과 승인 치료제가 다수 존재해 화합물-활성 데이터가 풍부하다.
- **활막(Synovium)**: 관절강을 둘러싼 조직. RA 염증의 병변 부위이며 생검 기반 분자 프로파일링이 확립되어 있다.
- **병리형(Pathotype)**: 활막 면역세포 조성 분류 — lymphomyeloid / diffuse-myeloid / fibroid. R4RA·STRAP 등 생검 기반 시험에서 사용.
- **불충분 반응**: 첫 TNF 억제제에 충분히 반응하지 않는 환자가 대략 3분의 1 수준으로 보고된다.
### 신약개발 방법론 관련
 
- **표적 발굴 vs 히트 발굴**: 전자는 "무엇을 겨냥할 것인가", 후자는 "그 표적에 결합하는 화합물". **본 프로젝트는 전자에 한정.**
- **성약성(Tractability)**: 표적에 약물이 접근 가능한가 — 세포외·막관통 여부(항체), 결합 포켓 유무(소분자).
- **cis-MR**: 표적 유전자 근방(cis) 변이만을 도구변수로 사용해 **인과 효과와 방향**을 추정. cis 변이는 trans보다 다면발현 가능성이 낮다.
- **Colocalization**: 질환 GWAS와 분자 QTL이 동일 인과 변이를 공유하는지 검정. MR과 병행하지 않으면 LD에 의한 허위 연관을 배제할 수 없다.
- **LOEUF**: gnomAD의 유전자별 loss-of-function 관용도. 낮을수록 LoF 비관용 — 필수성·안전성 대리 지표.
- **Three Pillars**: 임상 실패를 노출·표적 결합·기능적 약리로 귀속. **Pillar 3 실패만이 표적 가설을 반증**한다.
- **분자 도킹 / ADMET / SMILES**: 화합물의 결합력·약물 유사성·구조 계산 기법. 후속 트랙.
### Agent 관련
 
- **지식그래프**: 유전자·질병·약물 등 개체와 관계를 그래프로 표현한 DB. 새로운 연결고리 탐색에 사용.
- **ReAct**: think → act → observe 반복으로 다음 행동을 스스로 정하는 패턴. **L2 후보별 탐색 루프**가 해당.
- **Reflection**: 생성자가 산출물을 내고 비판자가 반박한 뒤 수정하는 루프. **L3 명제·반증 루프**가 해당.
- **벌크 기저**: 전 후보에 동일하게 깔리는 근거 집합. 비용이 후보 수와 무관해 전수 확보하며, 탐색이 백지에서 시작하지 않게 한다.
- **탐색 이력**: 후보별 탐색의 각 단계(판단·호출·결과·근거 버전) 기록. 재방문 시 재개의 근거.
- **결정 원장**: 사람의 판정을 사유 코드·근거 버전과 함께 append-only로 남기는 저장소.
- **근거 버전 고정**: 각 판정이 어느 스냅샷에 기반했는지 못박는 것. 없으면 "이 판정이 지금도 유효한가"에 답할 수 없다.
- **차분 엔진**: 근거 갱신 시 영향받는 판정만 재검토 큐에 되돌리는 장치.


## 3. 전체 아키텍처 개요
 
해당 아키텍처는 ReAct Framework를 기반으로 설계되었다.
가설 생성과 반증을 통해 후보를 발굴하고, 해당 후보에 대한 검증 가설을 수립하는 과정을 거친다.

[전체 아키텍처](./images/full_system_architecture.svg)

### 계층 구성

| 계층 | 역할 | 성격 |
|---|---|---|
| L1 수집 | 소스별 스냅샷 확보·버전 고정 | 결정론적 |
| L2 생성 | 후보 열거 → 심사 → 벌크 기저 → 후보별 ReAct 탐색 | 에이전트 |
| L3 정련 | 명제 구성 ↔ 반증 수집 (**Reflection**) → 카드 | 에이전트 |
| 원장 | 사람 판정을 사유 코드·근거 버전과 함께 append-only 기록 | 결정론적 |
| 차분 엔진 | 근거 갱신 감지 → 영향 판정 → 재검토 큐 | 결정론적 |

### 세 개의 루프
 
| 루프 | 위치 | 주기 | 종료 조건 |
|---|---|---|---|
| **ReAct 탐색** | L2 | 실행 내 | 에이전트 "충분" 판단 또는 호출 예산 |
| **Reflection** | L3 | 카드별 | 반증이 명제를 무효화하지 않음 또는 N회 |
| **재검토** | 메모리 | 몇 달 | 근거 갱신 시 자동 발동 |
 
근거 값과 근거 버전의 재현성은 유지하며 탐색 경로, 깊이, 반증 범위는 자율에 맡긴다.
대체적으로 Origene의 아키텍처에 따른다.

| 축 | 내용 | 인자 수 |

| **Association Evidence** (질환 특이, RA `EFO_0000685`) | genetic · expression · literature · animal · drug · pathway | 6 |

OT에 없는 둘을 제외한 모든 항목은 OT가 계산해 배포한다. 인자별 상세는 `L2.md` 참조.
 
> **원천 데이터와 집계 방식은 신뢰 수준이 다르다.** LOEUF·DepMap·COSMIC·ChEMBL tractability는 각 분야 표준이나, MGI 표현형 중증도 가중이나 4섹션 그룹핑은 OT의 설계 판단이며 예측력이 검증된 바 없다. **원천 값을 신뢰하되 단일 종합 점수 통합에는 신중을 기한다.**

### 3.4 제약 및 후속 확장
 
- 본 에이전트는 근거 기반 가설 및 후보 제안까지만 수행하며, wet-lab 검증은 인간 연구자에게 위임한다.
- PsA·AS는 병변 조직 데이터와 채점 기준이 없어 후속 확장으로 분리한다. OA·Gout은 표적 클러스터가 겹치지 않아 별도 스코프 문서로 분리한다.

**내재적 한계**
1. **입력 규격 고정** — OT 16인자·LOEUF·cis-MR은 단백질 부호화 유전자를 전제한다.
2. **도메인 데이터 의존성** — cis-MR은 GWAS·QTL이 축적된 질환에서만 구동된다. RA는 충족되나 이식 시 무효화될 수 있다.
3. **탐색 폭 축소** — 도구 집합이 좁아 예외적 질의 대응력이 낮다. 비교 가능성을 얻는 대신 폭을 잃는 교환이다.
4. **커버리지 비결정성** — 후보별 탐색 깊이가 다르므로 심화 근거가 균일하지 않다. 벌크 기저는 전수 확보되나 MR·문헌 심층은 후보마다 다르다.
5. **RA 전용 구현** — 데이터 배선·벤치마크가 RA 고유다. 이식 시 재사용되는 것은 파이프라인 형태와 코드 골격뿐이다.


## 4. 평가 방식
 
> **생물학적 타당성을 스스로 판정하지 않는다.** 근거를 시점으로 잘라 **과거 시점에서 미래를 예측할 수 있었는가**로 채점한다. 정답은 이후 실제로 임상에 진입한 표적이며, 우리가 만드는 것이 아니다.
 
평가는 두 축이다. **E1이 "작동하는가", E2가 "각 부품이 제 값을 하는가"**를 답한다. 나머지는 보조다.
 
### 4.1 E1 — 시간 분할 예측 (주 평가)
 
#### 설계
 
```
근거를 컷오프 T 이전으로 제한
        ↓
시스템 실행 → 순위 산출
        ↓
T 이후 RA 임상에 진입한 표적을 얼마나 상위에 두었는가
```
 
**후향 재현이 아니라 예측이다.** "당시 알 수 있었던 것만으로 미래를 맞혔는가"를 묻는다.
 
#### 정답 집합 구성
 
| 구분 | 정의 |
|---|---|
| **양성** | T 이후 RA 임상시험이 **처음** 개시된 표적. 단 T 이전에 RA 시험 이력이 없어야 함 |
| 배경 | 후보 풀의 나머지 |
| 제외 | T 이전에 이미 RA 승인·임상 진행 중이던 표적 |
 
출처: AACT의 시험 개시일 · 적응증 · 표적 매핑(ChEMBL 경유)
 
#### 누출 차단
 
**모든 소스를 T 시점으로 고정해야 한다.** 하나라도 새면 평가가 무효다.
 
| 소스 | 차단 방법 | 가능 여부 |
|---|---|---|
| Open Targets | **T 이전 분기 릴리스 사용** | ✅ EBI FTP 아카이브, 2019.07부터 |
| 문헌 검색 | 발행일 필터 | ✅ PubMed |
| AACT | 등록·개시일 필터 | ✅ 월별 정적 스냅샷 |
| GWAS 요약통계 | 발표일 기준 선정 | ✅ |
| **eQTL** | T 이전 릴리스 | ◐ GTEx v7/v8은 가능, **eQTLGen(2021)은 T=2020에 불가** |
| **pQTL** | — | ❌ **UKB-PPP는 2023 공개 — 2020 컷오프에 존재하지 않음** |
 
> ⚠️ **MR 구성요소의 시간 정합성 문제.** T=2020으로 잡으면 pQTL이 존재하지 않고 eQTLGen도 없다. GTEx eQTL만으로 축소 실행하고 **이 제약을 결과에 명시**한다. 또는 T를 2022 이후로 올려 데이터를 확보하되 양성 표적 수가 준다.
 
#### 지표
 
| 지표 | 정의 |
|---|---|
| **Recall@50** | 상위 50개 안에 든 양성 표적 비율 ← **대표 숫자** |
| Recall@100 | 보조 |
| 평균 순위 | 양성 표적들의 평균 순위 |
| 정규화 순위 | 후보 풀 크기로 정규화한 값 (풀 크기 변동 대비) |
 
#### 베이스라인 — 평가를 의미 있게 만드는 부분
 
| 베이스라인 | 답하는 질문 |
|---|---|
| 무작위 | 최소 기준 |
| **OT 연관 점수 단독 정렬** | **"그냥 Open Targets 쓰면 되지 않나"** |
| **최근성·빈도 정렬 단독** | **"OriGene 방식과 뭐가 다른가"** |
| 문헌 빈도 단독 | 인기 편향 대비 |
 
**2번과 3번이 심사에서 반드시 나올 질문에 수치로 답한다.**
 
#### 표본 수 위험 — Phase 0에서 최우선 확인
 
RA에서 2020~2026 신규 진입 표적이 **10개 미만이면 Recall이 불안정**해진다. 대응 순서:
 
1. 컷오프를 앞당김 (T=2018) — 양성 증가, 단 MR 데이터 더 부족
2. **면역매개 염증질환(IMID) 전반으로 확장** — RA·PsA·AS·IBD·건선·SLE. 기전을 공유하므로 표본이 크게 늘어남
3. 표적-적응증 쌍 단위로 계수
**주 평가는 RA로 하고, 표본이 부족하면 IMID 확장본을 강건성 검사로 병기한다.**
 
### 4.2 E2 — 절제 연구 (설계 정당화)
 
**각 행이 설계 결정 하나에 대응한다.** 주장이 아니라 수치로 정당화된다.
 
#### E2a — 순위에 영향을 주는 절제
 
E1과 동일한 설정에서 구성요소를 하나씩 제거하고 **ΔRecall@50**을 측정한다.
 
| 제거 대상 | 대응 설계 결정 | 예상 |
|---|---|---|
| **ReAct 탐색 루프** (벌크 기저만 사용) | 깊이 우선 채택 | 하락 |
| **cis-MR** | 인과·방향 추가 | 소폭 하락 (순위 기여가 제한적) |
| **벌크 기저** (탐색만) | 백지 시작 방지 | 하락 + 호출 수 급증 |
| **LLM 심사** | 노이즈 제거 | 하락 |
| **신규성 신호** (최근성·빈도) | OriGene 방식 채용 | 하락 |
 
#### E2b — 순위에 영향을 주지 않는 절제
 
메모리·Critic 등은 단일 실행 순위를 바꾸지 않으므로 **별도 지표**로 측정한다.
 
| 제거 대상 | 대응 설계 결정 | 측정 지표 |
|---|---|---|
| **메모리층** (원장·차분) | B안의 본체 | **재검토 복구율 → 0** |
| **Critic 분리** (동일 에이전트가 겸함) | 안전 요건(§3.2 규칙 1) | 반증 필드 충족률 · 후보 기각률 |
| **cis-MR** | 방향 결정 | `dir` 확정률 → 0 |
| 탐색 이력 기록 | 재개 가능성 | 재탐색 시 중복 호출 수 |
 
> **"Critic을 빼면 반증 수집률이 이만큼 떨어진다"**가 §3.2 설계 규칙 1의 실증이 된다.
 
#### 재검토 복구율 — 메모리층 전용 지표
 
E1의 시간 분할 장치를 재사용한다.
 
```
T 스냅샷으로 판정  →  T+3년 근거 주입  →  차분 엔진 발동
      ↓
뒤집힌 판정 중 실제로 임상에 진입한 표적이 있는가
```
 
**"T 시점에 기각했으나 이후 근거로 되살아났고, 실제로 개발이 진행됐다"** — 이 사례를 한 건이라도 재현하면 메모리층의 가치가 정량으로 증명된다.
 
### 4.3 보조 — 도구 정확성과 점검
 
E1·E2 이전에 도구가 맞는지 확인한다. **심사 노출은 한 줄로 충분하다.**
 
| # | 항목 | 기준 |
|---|---|---|
| S1 | **OT 값 정합성** | OT 원본과 불일치 0 |
| S2 | **기지 표적 회수** (컷오프 없이) | TNF · IL6R · MS4A1 · CTLA4 · JAK1/2 · IL1이 상위 5% |
| S3 | **IL6R MR 방향** | 억제 = RA 위험 감소. F > 10, MR-Egger 절편 비유의, coloc H4 ≥ 0.8 |
| S4 | 음성 대조 | RA 무관 유전자 10개가 하위 50% |
| S5 | 결측 처리 | NA가 0으로 대치되지 않음 |
| S6 | **근거 값 재현성** | 같은 스냅샷 N회 실행 시 **일치율 100%** |
| S7 | 명제·반증 완전성 | 상위 50개에 세 주장 + 출처 100%, 반증 필드 비지 않음 |
 
> **S1·S2가 관문이다.** 통과 전에는 E1으로 넘어가지 않는다. S1 실패는 조회·버전 오류, S2 실패는 열거·조인 오류로 **원인이 구분된다.**
>
> **S6이 §3 "기록되는 값은 결정론적"의 직접 증명이다.** 100%가 아니면 차분 엔진이 성립하지 않는다.
 
**IL-17A는 S2의 정답 집합에 넣지 않는다.** PsA·AS에서만 승인됐고 RA에서는 실패했으므로, 오히려 기전 특이성 점검에 쓴다 — RA에서 낮은 순위로 나와야 정상이다.
 
### 4.4 TRQA 활용 (선택)
 
OriGene의 TRQA 벤치마크(1,900여 문항)가 GitHub에 공개되어 있어, **직접 비교가 가능한 유일한 지점**이다.
 
| 서브셋 | 내용 | 활용 가능성 |
|---|---|---|
| TRQA-lit (객관식·단답) | 문헌 기반 표적 생물학 QA | ✗ 우리 산출물은 순위 목록이지 QA 답변이 아님 |
| **TRQA-db** | **DB 기반 경쟁 현황 QA** | ◐ **근거 행렬에서 직접 답변 가능** |
 
**TRQA-db를 근거 행렬 완전성 점검에 쓴다.** "우리 행렬이 이 질문에 답할 사실을 담고 있는가"를 묻는 것이며, OriGene의 공표 수치(72.05%)와 대조할 수 있다.
 
**제약** — TRQA는 다수 질환을 다루므로 **RA 관련 문항만 필터링**해야 하며, 그 결과 문항 수가 크게 줄어 통계적 의미가 약해진다. 따라서 **대표 지표가 아니라 보조 점검**으로 둔다.
 
### 4.5 심사 노출 우선순위
 
| 순위 | 항목 | 형태 |
|---|---|---|
| **1** | **E1 — Recall@50 vs 베이스라인 4종** | 표 하나 |
| **2** | **E2 — 절제별 ΔRecall / 전용 지표** | 표 하나 |
| 3 | S6 재현성 | 한 줄 (100%) |
| 4 | 재검토 복구 사례 | 사례 하나 |
| 부록 | S1~S7 · TRQA-db · 비용·궤적 | |
 
**E1과 E2 두 표가 심사의 전부여야 한다.**
